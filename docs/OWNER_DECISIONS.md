# Решения владельца

Журнал решений владельца, которые влияют на архитектуру, политику и приоритеты. Новые решения добавляются сверху; старые не удаляются — изменение оформляется новой записью со ссылкой на прежнюю.

Реализация обязана следовать этим решениям. Если решение противоречит конституции или ADR — остановиться и спросить владельца.

| D-022 | Уровень 3: первый коммерческий цикл | «Продолжай — нужно доделать всё, чтоб осталось только добавить api и старт». **Одобрен Уровень 3** в минимальном объёме (§2.15): система сама пишет лендинг теста, публикует его, считает воронку, собирает заявки и принимает оплату; владелец одобряет кнопками, ведёт рекламу и переводит выплаты. **Порядок фаз** (по зависимостям, предложен Claude): 19a Media Factory (лендинг и рекламные тексты, проверка владельцем) → 21 Solution Factory (Release Gate §7.2 и публикация на `api`) → 20 CRM / Outcomes (заявки, клиенты, итог клиента, удаление данных) → 20b приём оплат (ADR, merchant of record, провайдер выбирает владелец ключами). **Режим как D-020:** Claude идёт по фазам без остановок; у каждой — спецификация, тесты, отчёт и PR. Останавливается, только когда нужны действия владельца, ADR меняет стек сверх этого решения или деньги выходят за D-007. **Не меняется:** лимиты D-007, бюджет каждого теста — одобрением владельца, все решения — кнопками. **Вне решения:** видео и картинки (19b), автоматические рекламные кабинеты, этап F (18, 22, 23) — по итогам первых тестов. |

Решения внутри системы — всегда кнопками владельца.                                                                                                                                            |
