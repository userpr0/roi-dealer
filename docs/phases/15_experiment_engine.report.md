## Implemented

- **Единая воронка (D-014 п.9):**
  - девять шагов `FUNNEL_STAGES`: показ → внимание → клик → активация → заявка → оплата → использование → результат → возврат;
  - метрика успеха — количество шага или доля шага от более раннего;
  - значение и «достигнута ли» считает домен из сумм воронки (`metricValue`, `metricReached`), одинаково для любого теста (§7.3).
- **`design-hypotheses` версии 2:** модель выбирает шаг воронки и базу доли из списков; код проверяет порядок шагов и цель (доля — не больше 100 %).
- **Выбор гипотезы:**
  - кнопка «🧪 N» у каждой предложенной гипотезы в `/hypotheses`;
  - подтверждение показывает план;
  - одна команда владельца: гипотеза `selected`, эксперимент `planned`.
- **План в коде** (`planExperiment`, §7.1 C–D):
  - самый маленький артефакт для способа проверки;
  - $0 денег и $0 AI на сборку (Уровень 2), часы по артефакту, срок 14 дней;
  - бюджет, stop-loss и метрика — из гипотезы;
  - критерии остановки и ожидаемые доказательства — из её полей.
- **Чек-лист честной проверки (D-014 п.8, §7.2):**
  - 9 пунктов; применимые зависят от способа проверки и цены;
  - код сам отмечает: метрика и stop-loss зафиксированы, ценность описана результатом, траты ограничены;
  - владелец подтверждает список одной кнопкой (`confirmHonestChecks`), пункты и время хранятся в эксперименте;
  - **без чек-листа тест не стартует:** `startExperiment` бросает ошибку, CHECK `experiments_checks_before_start` не пускает строку.
- **Запуск (D-006, D-007):**
  - запрос `experiment_launch` на полный бюджет — в `/decisions`, срок 7 дней;
  - ✅ → `approveExperiment` (домен сверяет вид, сумму и предмет); ❌ → назад к планированию, чек-лист сохраняется;
  - истёкший запрос — «🚀 Запросить снова», старый помечается истёкшим;
  - «▶️ Тест запущен» → `running`, гипотеза `testing`, возможность `validating`.
- **`/funnel`:**
  - например `/funnel 1 клики 40 заявки 5 $12.50`;
  - шаги по-русски или ключами, числа — прирост;
  - подтверждение «было → станет», траты против stop-loss и бюджета, предупреждение о стопе;
  - одна команда: события, затраты и автостоп.
- **Траты:**
  - `recordExperimentCost` — `CostEntry` категории `ads` только для запущенного теста, со ссылкой на одобренный запуск;
  - сумма не выше одобренного бюджета, иначе ничего не записывается.
- **Автостоп** (`automaticStopReason`):
  - бюджет теста израсходован;
  - или stop-loss израсходован, а метрика не достигнута.
- **Итог (§7.1 H, §2.9):** 🚀 масштабировать / 🔧 улучшить / ↪️ сменить подход / 🛑 закрыть.
  - **Одна команда:**
    - `KnowledgeAsset` с итогом: `pattern` / `knowledge` / `failure_pattern`, теги `experiment-result` и способ проверки, ищется в `/search`;
    - `Decision` владельца об эксперименте;
    - `completed`;
    - статус гипотезы по данным (`hypothesisVerdict`).
  - **«Масштабировать»** переводит возможность в `scaling`, «закрыть» — в `killed`, оба через `Decision` о возможности.
  - **Закрыть возможность** можно, только когда других незавершённых тестов у неё нет.
- **`/experiments`:**
  - карточки незавершённых тестов с номерами;
  - статус и день из срока, оффер, цена, канал;
  - метрика сейчас и цель, воронка;
  - потрачено, бюджет, stop-loss;
  - причина остановки, просрочка;
  - кнопки по статусу.

## Security implications

- **Деньги:**
  - система ничего не тратит сама;
  - траты владельца записываются только в пределах одобренного запуска;
  - stop-loss останавливает тест в той же транзакции, что записала траты.
- **Честность:** без подтверждённого чек-листа тест не запускается ни в домене, ни в базе.
- **Права и журнал:**
  - кнопки и `/funnel` требуют `experiment.write` и пишутся в журнал доступа;
  - журнал событий воронки проверяет право сам;
  - в логах только id и признаки.
- **Приватность (ADR-0007):** события без персональных данных, сторонней аналитики нет.

## Cost implications

- **$0:**
  - новых сервисов нет;
  - AI в экспериментах не участвует;
  - воронка — в той же PostgreSQL.
- **Рекламные бюджеты:** каждый тест одобряется отдельно на полный бюджет (D-007), не больше $100 на гипотезу (PHASE 14).

## Known limitations

- **Тест запускает владелец:** публикует страницу или рассылку; система ведёт тест и считает. Реклама через API площадок и приём платежей — Уровень 3.
- **Сбор событий со своих страниц** (`tracker`) — с `apps/api` (PHASE 13) и страницами (PHASE 19).
- **Номера в `/funnel`** — порядковые среди незавершённых тестов. Подтверждение показывает название теста, поэтому ошибку видно до записи.
- **Остановки по сроку нет:** на карточке просроченного теста видна пометка, итог подводит владелец (§2.15).

## Scope decisions

- **Метрика — шаг воронки (v2 задачи гипотез):** иначе метрику нельзя посчитать детерминированно (§7.3). PHASE 14 ещё не влита, поэтому смена версии задачи ничего не ломает.
- **Чек-лист одной кнопкой:** владелец видит список и подтверждает его целиком — две нажатия вместо двенадцати; в базе хранится каждый пункт.
- **Цифры — приростом:** подтверждение «было → станет» защищает от двойного счёта.
- **«Сменить подход» не создаёт новую возможность:** это появится, когда система сможет её предложить. До тех пор владелец выбирает другую гипотезу.

## Business hypothesis enabled by this phase

Владелец берёт гипотезу, честно и дёшево её проверяет и получает решение по данным. Любой результат остаётся в базе знаний, деньги — под stop-loss.

## Authoritative data paths verified

```text
/hypotheses 🧪 N → [подтверждение] → hypothesis.select: Hypothesis selected + Experiment planned (planExperiment)
/experiments ☑️ → [список чек-листа] → experiment.act: confirmHonestChecks + ApprovalRequest experiment_launch + awaiting_approval
/decisions ✅ → approval.resolve: approveExperiment → ▶️ → startExperiment (только с чек-листом) → validating
/funnel → [было → станет] → experiment.funnel: experiment_events + recordExperimentCost → automaticStopReason → stopped
🏁 → experiment.act: KnowledgeAsset + Decision + completeExperiment + hypothesisVerdict (+ Decision о возможности)
```
