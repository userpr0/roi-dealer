# PHASE 13a — Telegram Owner Bot

> **Происхождение:** ранний шаг PHASE 13 (Owner Command Center), выполненный по прямому запросу владельца до PHASE 01.
> **Решение:** [ADR-0003](../ADR/0003-early-telegram-owner-bot.md). **Отчёт:** [13a_telegram_owner_bot.report.md](13a_telegram_owner_bot.report.md).

## Objective

Защищённый канал управления в Telegram: бот, который отвечает только владельцу, показывает состояние системы и присылает уведомления. Бот работает в облаке 24/7 как один Docker-контейнер.

## Business purpose

Owner Command Center (система 14) и будущий Input Router (система 16) получают проверенный транспорт до появления бизнес-данных. Позже через этот канал пойдут approvals (human gates, §2.7), alerts и отчёты.

## Scope

1. Пакет `@roi-dealer/telegram`: клиент Bot API (`fetch` + Zod), long polling, маршрутизатор команд только для владельца, notifier.
2. `apps/bot`: команды `/start`, `/status`, `/help`; уведомления о запуске и остановке; меню команд только в чате владельца.
3. `apps/bot/Dockerfile` + сборка образа в CI.
4. Инструкция по развёртыванию: `docs/deploy/telegram-bot.md`.

## Out of scope

- Данные в Mini App, проверка `initData`, публичный API.
- Команды, меняющие состояние системы.
- Webhook, группы, другие пользователи, несколько владельцев.
- Создание облачных ресурсов (аккаунт хостинга создаёт владелец).

## Hard constraints

- Токен только из окружения; не логируется и не попадает в ошибки, образ и repository.
- Только личные сообщения от `TELEGRAM_OWNER_USER_ID`; текст сообщений не логируется.
- Bot API только по HTTPS (HTTP — только localhost для тестов).
- Без новых runtime-зависимостей.
- Завершение укладывается в 10 s окно SIGTERM → SIGKILL.

## Acceptance criteria

1. Бот отвечает владельцу на `/start`, `/status`, `/help`; на прочий текст — подсказкой.
2. Сообщения других пользователей и групп игнорируются без ответа.
3. Владелец получает уведомления о запуске и остановке.
4. Неверный токен → exit 1 без утечки токена; некорректная конфигурация → exit 1 без значений.
5. 409 / 429 / сетевые ошибки не роняют бот (backoff).
6. Docker-образ собирается, контейнер работает и завершается по SIGTERM с кодом 0.
7. typecheck, lint, format, unit + integration tests, build — зелёные; CI собирает образ.
