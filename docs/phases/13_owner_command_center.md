## Objective

Пульт закрывает весь план кнопок:

- **📊 статистика** цикла и метрики самой системы;
- **недельный разбор** с предложениями SCALE / IMPROVE / PIVOT / KILL и кнопками;
- **⚠️ алерты** в дайджесте;
- **управление возможностями в работе** — ⏸ / ▶️ / ⛔;
- **отклонение лишних болей**;
- **Mini App с данными:** открывается из Telegram, показывает экономику, тесты и статистику. Данные отдаёт `api` только владельцу, после проверки подписи Telegram.

## Business purpose

- **Около 15 минут в неделю** (D-014 п.12): раз в неделю владелец видит итог и решает по готовым предложениям.
- **Видно, работает ли система** (D-014 п.11): время от сигнала до решения, ROI, цена проверенной гипотезы, новые знания.
- **Шум убирается рукой владельца:** лишние боли и возможности закрываются, а не копятся.

## Scope

### Часть A — бот

#### 1. `/stats` (📊, D-014 п.11)

**Поток цикла за 30 дней и за всё время:**

- доказательства → сигналы → боли (из них подтверждённые);
- возможности (черновики, на решении, одобренные);
- гипотезы → тесты (запущенные, завершённые);
- клиенты и выручка.

**Метрики системы:**

- **время от сигнала до решения** — медиана в днях: от первого сигнала болей возможности до решения владельца по ней;
- **новые знания** — без отчётов evals и служебного рыночного контекста;
- **ROI системы** и **стоимость проверенной гипотезы** — за месяц, как в `/economics`.

Всё считают фиксированные SQL-запросы (`database.stats`), с указанием источника. Право — `history.read`.

#### 2. Недельный разбор (D-014 п.12)

- **По понедельникам в 10:00 Киева** вместо дневного дайджеста; тот же планировщик, тот же ключ `digest-<дата>`.
- **Состав:**
  - решения за неделю по исходам;
  - итоги тестов за неделю;
  - расходы месяца против лимитов;
  - новые знания;
  - метрики системы;
  - затем дневной дайджест — очередь решений и стоп-кран.
- **Предложения системы — правила в домене** (`proposeExperimentOutcome`):
  - метрика достигнута → 🚀 масштабировать;
  - тест остановлен stop-loss или бюджетом без метрики → ↪️ сменить подход;
  - срок вышел, метрики нет → 🔧 улучшить;
  - иначе — без предложения: данных ещё мало.
- **Каждое предложение — отдельным сообщением:** карточка теста, предложение и кнопки «итог как предложено» и «другой итог». Кнопки ведут в обычный поток итога PHASE 15 с подтверждением. Решает владелец.
- **Ручная команда:** `/review` присылает разбор в любой день, без предложений-кнопок, только текст.

#### 3. Алерты в дайджесте (⚠️)

- **Сбои за сутки:**
  - упавшие запуски агентов → `/agents`;
  - ошибки вызовов AI — строка AI уже есть.
- **Просроченные тесты** → `/experiments`.
- **Автопауза** — строка стоп-крана и сообщение PHASE 16.

#### 4. `/portfolio` (💼) — возможности в работе

- **Возможности** `approved`, `validating`, `scaling`, `paused`:
  - статус;
  - тесты: идут и завершены;
  - выручка и клиенты.
- **Кнопки:**
  - ⏸ Пауза → `pause`;
  - ▶️ Продолжить (с паузы) → `improve`, снова на проверке;
  - ⛔ Закрыть → `kill`.
- **Каждое нажатие** — подтверждение, затем одна команда владельца: `createDecision` + `applyOpportunityDecision`; кнопки несут версию.
- **Пауза и закрытие** не выполняются, пока у возможности есть незавершённые тесты: сначала остановите или отмените их в `/experiments`.

#### 5. Отклонение болей в `/pains`

- **Под списком — кнопки «✖️ N».** После подтверждения боль становится `rejected` (`changePainStatus` от владельца).
- **Агент болей отклонённую больше не пополняет:** он работает только с открытыми болями.
- **Слияние болей** — нет (§2.15): дубли уже ловит `match-pain`.

### Часть B — Mini App с данными

#### 6. Проверка `initData` (`@roi-dealer/telegram`)

- **`verifyInitData(initData, botToken, nowMs)`** по алгоритму Telegram:
  - `secret = HMAC_SHA256(key="WebAppData", botToken)`;
  - `hash = HMAC_SHA256(secret, data_check_string)`;
  - сравнение в постоянное время;
  - свежесть `auth_date` — не старше 24 часов;
  - из `user` берётся только `id`.

#### 7. `apps/api`: `GET /api/panel`

- **Заголовок** `Authorization: tma <initData>`.
- **Без подписи, с чужой подписью или устаревшей** → `401`. Не владелец → `403`. Без базы → `503`.
- **Ответ — снимок пульта:**
  - очередь решений;
  - стоп-кран;
  - экономика месяца;
  - тесты с метрикой и деньгами;
  - статистика.
- **Только чтение.** Каждый просмотр — в журнал доступа (канал `miniapp`, право `status.read`). Изменения — только кнопками в боте.
- **CORS** — только для origin Mini App (`MINIAPP_ORIGINS`, по умолчанию `https://userpr0.github.io`); `OPTIONS` для preflight.
- **Логика снимка** — в `@roi-dealer/command-center` (`panelSnapshot`); `apps/api` её только подключает.
- **Конфигурация:** `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OWNER_ID`, `DATABASE_URL`, `MINIAPP_ORIGINS`. Токен нужен только для проверки подписи и в логи не попадает.
- **Docker-образ `apps/api/Dockerfile`** — как у бота.

#### 8. `apps/miniapp`

- **Telegram WebApp SDK** — официальный скрипт `telegram-web-app.js`. `initData` уходит в `api`.
- **Экраны — одна страница:**
  - решения;
  - экономика с полосками лимитов;
  - тесты;
  - поток цикла;
  - метрики.
- **Без библиотек графиков** (§2.15).
- **Адрес `api`** — переменная сборки `VITE_API_URL` из переменной репозитория `MINIAPP_API_URL`. Без неё Mini App честно пишет, что данные ещё не подключены.

## Out of scope

- **Изменения из Mini App** — только просмотр: решения остаются кнопками в боте с подтверждением.
- **Настройки уведомлений** и изменение лимитов — когда понадобятся (§2.15).
- **Слияние болей вручную** (§2.15).
- **Добавление Evidence вручную** — нужен отдельный источник каталога с проверенными правилами (PHASE 05); сейчас заметки — `/note`.

## Acceptance criteria

1. **`/stats`** показывает поток цикла и метрики D-014 п.11 из БД с источником.
2. **В понедельник 10:00 Киева** приходит недельный разбор с предложениями и кнопками, по одному разу на неделю; решает владелец.
3. **Дайджест** показывает сбои агентов и просроченные тесты.
4. **`/portfolio`:** пауза, продолжение и закрытие — с подтверждением, одной командой, решением владельца. Пока есть незавершённые тесты — отказ.
5. **Отклонение боли** — с подтверждением, от владельца.
6. **`GET /api/panel`** отдаёт данные только при верной и свежей подписи Telegram от владельца. Проверено тестами с поддельными подписями. CORS — только origin Mini App.
7. **Mini App** показывает снимок пульта, без секретов в сборке.
8. typecheck, lint, format, тесты, build, образы бота, worker и api — зелёные.

## Действия владельца после вливания

1. **Railway:** сервис `api` по [docs/deploy/api.md](../deploy/api.md). Переменные: `DATABASE_URL`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_OWNER_ID`. Публичный домен.
2. **GitHub → Settings → Variables:** `MINIAPP_API_URL` = адрес сервиса `api`. Mini App пересоберётся после следующего зелёного CI.
3. **Стоимость:** ещё один небольшой сервис в Railway — в пределах лимита инфраструктуры $20 в месяц (D-007). Проверьте в `/economics` после первого счёта.
