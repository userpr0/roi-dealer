## Objective

Агенты системы работают по одним правилам и видны владельцу. Добавляются два агента, которых не хватает конвейеру:

- **агент исследований** ищет новые доказательства к найденным болям;
- **агент рыночного контекста** собирает альтернативы, цены и покупателей — только то, что подтверждено цитатами.

## Business purpose

- **Больше доказательств на боль:** сейчас Evidence приходят только из свежих постов Ask HN, случайно. Агент исследований ищет посты именно про найденную боль. Частота растёт быстрее, и до возможности доходят настоящие повторяющиеся проблемы (§7.1 A).
- **Рынок для судей:** судьям (PHASE 11) и карточке решения (PHASE 12) нужно знать, чем люди решают проблему сейчас и сколько платят. Агент собирает это из Evidence с проверкой цитат. Без выдуманных конкурентов и размеров рынка (§2.5).
- **Контроль владельца:** `/agents` показывает каждого агента — доступ, последний запуск, что сделано и сколько стоил AI за сутки.

## Scope

### 1. Общие правила агентов — `@roi-dealer/agents`

- **Определение агента:** ключ, актор `agent:<ключ>`, запрос доступа (название и назначение для владельца), AI-задачи, функция одного запуска.
- **Один запуск (`runAgent`):**
  1. стоп-кран — первым шагом; на паузе запуск ничего не пишет;
  2. запрос доступа: при первом запуске — карточка в `/decisions`;
  3. работа агента: только при активной личности;
  4. строка в журнале запусков `agent_runs`.
- **Один планировщик на всех:** у каждого агента свой интервал, запуски идут по очереди, два запуска одного агента не пересекаются. При остановке worker вызовы AI прерываются, планировщик ждёт текущий запуск.
- **Агенты болей и возможностей** переходят на общий планировщик; их отдельные планировщики удаляются (технический долг PHASE 07).

### 2. Журналы — миграция `0010_agents`

- **`agent_runs`** — один запуск агента, только добавление:
  - агент, начало и конец;
  - итог: `done` / `idle` / `no_access` / `stopped` / `failed`;
  - число обработанных, причина остановки (`budget` / `unavailable` / `failed`), код сбоя;
  - `correlation_id`.
- **`agent_work`** — работа агента над одним объектом, только добавление:
  - агент, объект (`pain` / `opportunity`), его id и версия — уникально: одна версия объекта разбирается агентом один раз;
  - задача и её версия;
  - итог: `done` / `empty` / `rejected` / `failed`;
  - результат — небольшой `jsonb`: запрос поиска, число новых Evidence, снимок, id знания;
  - актор, `correlation_id`.
- **Тексты** не хранятся, кроме короткого поискового запроса (только латинские буквы, цифры и пробелы, до 60 символов).

### 3. Агент исследований (`researcher`)

- **Берёт** до 3 болей за запуск, раз в 6 часов:
  - статус `candidate`;
  - меньше 3 сигналов;
  - версия ещё не исследована.

  Сначала самые тяжёлые и недавно обновлённые.

- **AI-задача `research-query`** (bulk, доля дня 3 %, эталон 20 примеров): 1–2 коротких английских поисковых запроса — слова, которыми люди описали бы эту проблему.
- **Код проверяет запрос:** только латинские буквы, цифры и пробелы, 2–5 слов, до 60 символов. Нет годного запроса → `rejected`.
- **Поиск — через тот же источник Hacker News:**
  - **HN Search API** (Algolia, `hn.algolia.com/api/v1`) — поиск, на который ведёт сам сайт HN;
  - только посты Ask HN;
  - сервер возвращает только `objectID`, заголовок, текст и время — без автора (`attributesToRetrieve`);
  - до 10 новых постов на запрос; уже сохранённые пропускаются.
- **Сбор — общим путём PHASE 05** (`collectEvidence`):
  - стоп-кран, каталог, активный доступ интеграции Hacker News;
  - очистка персональных данных и имён;
  - снимок загрузки.

  Evidence записывает интеграция HN, как обычные загрузки. Агент болей разберёт их на следующем запуске.

- **Каталог:** у записи `hacker-news` появляется адрес поиска и условие «поиск Ask HN по словам боли: до 10 постов на запрос». Отдельных условий у HN Search API не опубликовано, как и у основного API. Объём: до 3 запросов за 6 часов, при заявленных сторонними источниками 10 000 в час.

### 4. Агент рыночного контекста (`market-analyst`)

- **Берёт** до 3 черновиков возможностей за запуск, раз в 6 часов: статус `draft` или `under_review`, версия ещё не разобрана.
- **Материал:**
  - до 8 Evidence болей возможности;
  - до 4 похожих Evidence из Company Brain (`database.brain.search`, любое слово заголовка и ICP).

  У каждой цитаты номер E1…E12.

- **AI-задача `market-context`** (bulk, доля дня 7 %, эталон 20 примеров). Каждый пункт — с дословной цитатой и номером:
  - **альтернативы** — чем люди решают проблему сейчас: продукт, сервис, ручная работа, своя разработка;
  - **цены** — упомянутые суммы и период: разово, месяц, год, час;
  - **покупатели** — кто платит или решает.
- **Код:**
  - оставляет пункт, только если цитата есть в названном Evidence;
  - сумму берёт из самой цитаты (`$400`, `$1.5k`), а не из ответа модели (§2.13).
- **Результат** — `KnowledgeAsset` вида `market_data` с тегом `market-context`:
  - связь с возможностью и цитируемыми Evidence;
  - описание для людей;
  - структура для судей — JSON в `body`.

  Ничего не подтвердилось → итог `empty`, знание не создаётся.

- **В `/opportunities`** — строка «Рынок: альтернатив N, цены: $400/мес…», если контекст есть.

### 5. `/agents` в пульте

- **Каждый агент**, запросивший доступ:
  - статус доступа: работает / ждёт решения в `/decisions` / приостановлен / отозван;
  - последний запуск и его итог;
  - за сутки: запусков, обработано, стоимость AI (`ai_calls` по актору агента).
- **Право** `status.read`; просмотр — в журнале доступа.

### 6. Бюджет AI (D-021)

- **Доли дня после фазы:**
  - вычистка имён 10 %;
  - сигналы 15 %, группировка 5 %;
  - возможности 10 %;
  - **исследования 3 %, рыночный контекст 7 %**;
  - evals 20 %;
  - резерв судей (PHASE 11) — 30 %.
- **Первый прогон эталонов** двух новых задач на трёх дешёвых моделях — около $0.05.

### 7. Worker

- `RESEARCH_INTERVAL_MS` и `MARKET_INTERVAL_MS` — по умолчанию 6 часов.
- Агенты запускаются только при ключах AI; evals новых задач — в обслуживании AI.

## Out of scope

- **Агент знаний** — PHASE 12, вместе с решениями.
- **Новые источники** (Stack Exchange, Bluesky) — после проверки их условий; агент исследований ищет только в разрешённых.
- **Размеры рынков и конкуренты вне Evidence** — только если появится разрешённый источник таких данных (§2.5); выдуманные моделью данные не сохраняются.
- **Комментарии HN** — выше риск персональных данных; только посты Ask HN.
- **Управление агентами из пульта** (запуск вне расписания, интервалы) — по необходимости, PHASE 13.

## Acceptance criteria

1. Каждый агент работает через `runAgent`:
   - стоп-кран останавливает до любого запроса;
   - без активного доступа — только запрос доступа;
   - каждый запуск записан в `agent_runs`.
2. Агенты болей и возможностей работают через общий планировщик; процесс-тест worker «пост → боль → возможность» проходит.
3. Агент исследований:
   - запрос проверен кодом;
   - новые Evidence приходят через HN Search с очисткой и снимком;
   - известные посты не загружаются повторно;
   - одна версия боли исследуется один раз;
   - без доступа HN поиск не выполняется.
4. Агент рыночного контекста:
   - сохраняет только пункты с цитатами, найденными в названных Evidence;
   - сумма берётся из цитаты;
   - пустой результат знания не создаёт;
   - одна версия возможности разбирается один раз.
5. У обеих новых задач — эталон от 20 примеров, оценка и доля дня; все доли вместе с evals ≤ 1, резерв покрывает худший вызов.
6. `/agents` показывает доступ, последний запуск и сутки по каждому агенту.
7. Тексты постов, промпты и ответы AI не попадают в логи.
8. typecheck, lint, format, тесты, build, оба образа — зелёные.

## Действия владельца после вливания

1. `/decisions` → «Доступ: Агент исследований» → ✅ → **Да**.
2. `/decisions` → «Доступ: Агент рыночного контекста» → ✅ → **Да**.
3. Проверить `/agents`.
