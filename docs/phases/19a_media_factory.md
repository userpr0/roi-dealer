## Objective

Для каждого теста, которому нужен лендинг, система сама пишет страницу и три рекламных текста. Владелец смотрит предпросмотр и решает: ✅ одобрить или ❌ переписать. Цифры (цену) и честные пометки («в разработке», «возврат денег») ставит код, а не модель.

## Business purpose

- **Тест без ручной сборки страницы:** раньше владелец собирал лендинг сам на внешнем конструкторе. Теперь он только проверяет готовый текст.
- **Честность по умолчанию** (§2.17, D-014 п.8): без выдуманных отзывов, цифр и гарантий; пометка «продукт в разработке» и условия возврата — всегда.
- **Cost per Approved Asset** (D-012): видно, во сколько обходится одобренный лендинг.

## Scope

### 1. Задача `write-landing` (`@roi-dealer/media`, новый пакет)

- **Вход:** гипотеза (аудитория, оффер, цена, канал, креатив, CTA, способ проверки) и возможность (клиент, проблема, изменение, измеримый результат). Цена — только числом из гипотезы.
- **Выход — структура:**
  - заголовок (до 90 символов), подзаголовок (до 200), проблема (до 300);
  - три выгоды (заголовок до 60, текст до 160), три шага «как это работает» (до 140);
  - оффер (до 200), период цены (`one_time`, `per_month`, `per_year`, `per_user_month`), кнопка (до 40);
  - 2–4 вопроса и ответа (до 120 / 300);
  - три рекламных текста для канала гипотезы (заголовок до 60, текст до 150).
- **Тир `bulk`:** дешёвые модели, выбор по эталонам (PHASE 09). Доля дня — 3 % (у судей — 22 % вместо 25 %: сумма долей остаётся 100 %).
- **Эталон:** 20 гипотез с разными клиентами; проходит, если ≥ 85 % ответов проходят проверку кода, ≥ 80 % заголовков про клиента или проблему и ≥ 90 % ответов получены.

### 2. Проверка кодом (`toLandingContent`)

- **Длины и наличие** всех частей.
- **Без выдумок:** отзывы, «trusted by», число клиентов, звёзды и рейтинги, награды, «гарантия», «без риска», «осталось N», «лучший / №1» — отклоняются.
- **Без цифр денег от модели:** суммы `$…` допустимы, только если они есть во входе (измеримый результат или оффер). Цену показывает код.
- **Без ссылок, почты и телефонов** в тексте.
- **Только английский** (рынки D-008).

Не прошло — одна повторная попытка со списком замечаний, как у гипотез.

### 3. Честная пометка и цена — код (`landingDisclosure`)

- `preorder` → «Предзаказ: оплата вперёд, полный возврат, если не выпустим».
- `landing_page`, `waitlist`, `ads_test` → «Продукт в разработке: оставьте почту — напишем, когда будет готов».
- Цена: `$12 / month` из гипотезы и периода; цена 0 → «Free while in early access».

### 4. Сущность `MediaAsset` (миграция `0015`)

- **Поля:**
  - вид `landing`;
  - тест, гипотеза, возможность;
  - содержимое (проверенная структура, цена, пометка) — JSON-текст до 20 000 символов; база проверяет, что это JSON-объект, код при чтении — схему домена;
  - `slug` для будущего публичного адреса;
  - `previewToken` (128 бит) для закрытого предпросмотра.
- **Жизненный цикл:** `draft` → `approved` | `rejected`; `approved` → `released` | `retired`; `released` → `retired`. В 19a используются `draft`, `approved`, `rejected`; выпуск — PHASE 21.
- **Одобряет и отклоняет только владелец** (`approveMediaAsset`, `rejectMediaAsset`).
- **База:** один живой (`draft`, `approved`, `released`) лендинг на тест — уникальный индекс; версии, события, без удаления.

### 5. Агент `landing-writer` (`@roi-dealer/agents`)

- **Доступ** — запрос в `/decisions`, стоп-кран — первым шагом (как у всех агентов).
- **Берёт тесты** с артефактом `landing` в статусах `planned`, `awaiting_approval`, `approved`, у которых нет живого лендинга.
- **Переписывает** после ❌ владельца: не больше двух переписываний на тест. Во вход — отклонённый заголовок, чтобы зайти с другой стороны.
- **Журнал `agent_work`:** первый текст — по версии теста, переписывание — по версии отклонённого лендинга. Каждая работа один раз.
- **Расписание:** worker, `LANDING_INTERVAL_MS` (15 минут).

### 6. Пульт

- **Карточка «🎨 Лендинг для теста №N»** приходит сама, один раз на версию:
  - заголовок, подзаголовок, выгоды, цена с пометкой, кнопка;
  - рекламные тексты;
  - ссылка на предпросмотр, если задан `PUBLIC_API_URL`.
- **Кнопки ✅ Одобрить / ❌ Переписать** → подтверждение → одна команда владельца. Устаревшая карточка ничего не меняет.
- **Карточка теста** в `/experiments` — строка «🎨 Лендинг: …» (пишется, ждёт ✅, одобрен, переписывается).
- **`/economics`** — Cost per Approved Asset за месяц: стоимость вызовов `write-landing` по журналу AI, делённая на одобренные лендинги месяца.

### 7. Предпросмотр (`apps/api`)

- **`GET /p/<token>`** — страница лендинга по шаблону.
- **Безопасность:**
  - `noindex`;
  - без JavaScript, без внешних ресурсов, строгий CSP;
  - всё содержимое экранировано.
- **Нужна только база.** Неизвестный токен — 404.
- **Шаблон `renderLanding`** — один на предпросмотр и будущую публикацию (PHASE 21).

## Out of scope

- **Картинки и видео** (19b), Motion Reference, Brand Kit — когда тесты покажут, что текста мало (§2.15).
- **Правка текста владельцем вручную** — ❌ и переписывание агентом. Свои правки — когда понадобятся.
- **Публикация, трекинг, форма заявки, оплата** — PHASE 21, 20, 20b.

## Acceptance criteria

1. Для теста с артефактом `landing` агент пишет лендинг. Код отклоняет выдумки, чужие цифры денег, ссылки и не-английский текст.
2. Цену и честную пометку ставит код по гипотезе.
3. Карточка приходит один раз на версию. ✅ / ❌ — с подтверждением, от владельца. После ❌ агент переписывает (не больше двух раз).
4. `GET /p/<token>` показывает страницу без скриптов и внешних ресурсов, всё экранировано.
5. Один живой лендинг на тест — в домене и в базе.
6. typecheck, lint, format, тесты, build, образы — зелёные.

## Действия владельца после вливания

- `/decisions` → «Доступ: Автор лендингов» → ✅.
- В Variables бота — `PUBLIC_API_URL` (адрес сервиса `api`), чтобы в карточке была ссылка на предпросмотр. Без него карточка показывает текст.
