## Objective

Владелец находит в базе всё, что система узнала: боли, возможности, доказательства, знания, решения. Он может:

- найти запись;
- задать вопрос и получить ответ из БД с указанием источника;
- записать своё знание.

Для следующих фаз (судьи, карточка решения) готов поиск похожих прошлых случаев.

## Business purpose

- **Знания не теряются (§2.9):** каждый цикл оставляет то, что можно найти и использовать снова.
- **Цифры не выдумываются (§2.13, §7.3):** ответ про деньги или количество посчитан запросом к БД и показан с источником.
- **«Retrieve historical knowledge»** — шаг первой рабочей версии ROI Dealer (SYSTEM_ARCHITECTURE §11).

## Scope

### 1. Полнотекстовый поиск — миграция `0009_company_brain`

- **Индексы:** GIN-индексы выражений `to_tsvector('english', …)`. Новых колонок и копий данных нет. Индексы стоят на:
  - болях — заголовок, описание, аудитория, результат;
  - возможностях — заголовок, описание, ICP, ценностное предложение;
  - Evidence — цитата;
  - знаниях — заголовок, описание, тело;
  - решениях — обоснование.
- **Язык — английский:** тексты болей и возможностей — английские (посты и ответы AI).
- **Запрос:** `websearch_to_tsquery` с текстом как параметром.
  - точный поиск — все слова;
  - похожие случаи — любое из слов, по рангу.
- **Отчёты evals** (тег `eval`) в поиск не попадают.

### 2. `/search <слова>`

- **Ответ:** до 10 результатов по всем видам. Для каждого — вид, заголовок, фрагмент с найденными словами, дата.
- **Нет точных совпадений** — показываются похожие (любое из слов).
- **Слова только кириллицей** — подсказка искать английскими словами (данные английские) или спросить через `/ask`.
- **Право** `research.read`; просмотр записывается в журнал доступа.

### 3. `/ask <вопрос>` — ответ только из БД (§7.3)

Код распознаёт вопрос по правилам — русские и английские слова:

| Вопрос                                     | Запрос в БД                                                       | Источник в ответе                      |
| ------------------------------------------ | ----------------------------------------------------------------- | -------------------------------------- |
| «сколько потратили за неделю?»             | сумма `cost_entries` за период (сторно вычитается), по категориям | `/history`                             |
| «сколько ушло на AI за месяц?»             | сумма `ai_calls` за период, вызовы и ошибки                       | журнал `ai_calls`, `/status`           |
| «сколько болей / возможностей / сигналов?» | число по статусам и созданных за период                           | `/pains`, `/opportunities`, `/journal` |
| «что нового за день?»                      | созданные за период боли, возможности, доказательства, сигналы    | `/journal`                             |
| иначе                                      | поиск по словам вопроса, как `/search`                            | найденные записи                       |

- **Период:** сегодня, вчера, неделя, месяц, всё время. По умолчанию — месяц (для денег) и всё время (для количеств).
- **Ответ** собирает шаблон из чисел запроса. AI не участвует:
  - ни одна цифра не придумана;
  - ключи AI остаются только в worker ([ADR-0006](../ADR/0006-ai-providers-and-runtime.md)).
- **Право** `research.read`.

### 4. `/note <текст>` — знание владельца

- Создаёт `KnowledgeAsset` (`kind: knowledge`, тег `owner-note`):
  - заголовок — первая строка (до 120 символов);
  - описание — текст (до 3 000).
- **Состояние меняется, поэтому:**
  - сначала подтверждение кнопкой, оно действует 10 минут;
  - затем идемпотентная команда БД (`tg-callback-<id>`) от `owner`.
- Записанное знание сразу находится через `/search`.
- **Право** `research.write`.

### 5. Похожие случаи

- `similarCases(text)` — возможности, знания и решения, похожие на текст. Ищутся по любому из слов, сортируются по рангу; переданные записи исключаются.
- Используется в `/search` и в карточке решения (PHASE 12).

## Out of scope

- **Векторный поиск (embeddings)** — только через ADR, если словесного поиска окажется мало.
- **AI-ответы на вопросы** — с Mini App (PHASE 13), если правил окажется мало: тогда ключ AI понадобится и боту.
- **Ручное добавление Evidence и расходов** — PHASE 13 и 16.
- **Метрики системы и воронка** — PHASE 13.

## Acceptance criteria

1. `/search` находит каждый вид записей. Отчёты evals не находятся. Без точных совпадений показываются похожие; на кириллицу — подсказка.
2. `/ask` отвечает:
   - на вопросы о деньгах (сторно вычитается), об AI, о количествах и новостях — числами из БД и с источником;
   - на прочие вопросы — результатами поиска.
3. `/note`: запись только после подтверждения; повтор нажатия не создаёт вторую запись; устаревшее подтверждение не записывает.
4. Запросы параметризованы: текст пользователя не попадает в SQL. Любые символы во вводе не ломают поиск.
5. Просмотры и запись — в журнале доступа; тексты сообщений не попадают в логи.
6. typecheck, lint, format, тесты, build, оба образа — зелёные.

## Действия владельца после вливания

Нет. Команды `/search`, `/ask`, `/note` появятся в меню бота после деплоя.
