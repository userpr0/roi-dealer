# 05b — Новые источники данных: требования владельца

> **Статус:** требования записаны до фазы (D-026). Спецификация `05b_sources.md` обязана их включить.
> **Основание:** D-026 («Что можно подключить законно — давай сразу всё подключать!»), D-024, D-019.
> **Принципы:**
>
> - §2.5 — сначала доказательства;
> - §2.20 — паттерн, а не копия;
> - §2.21 — только разрешённый доступ: официальный API, сначала условия, потом код;
> - §2.15 — Feature Kill Gate.

## Зачем

- **Второй источник болей.** Сейчас источник один — Hacker News. Боль подтверждается, только когда её видно в двух источниках (`MIN_SOURCES_FOR_VALIDATED_PAIN`). Без второго источника боли остаются кандидатами, а у оценки возможности не хватает баллов за «источники».
- **Сигналы спроса.** Растёт ли тема и сколько людей её ищут. Это добавляет к оценке реальные цифры о рынке, а не только цитаты.

Уже решено:

- **Hacker News** — `allowed`.
- **Reddit** — только по договору.
- **CFPB** — `rejected`: CFPB снимает тексты жалоб с публикации.
- **GitHub** — `rejected`, §6–7 Acceptable Use Policies.
- **Google Trends без официального API** — неофициальные библиотеки и сервисы выгрузки результатов Google нарушают его условия. Официальный API — `needs_agreement`: владелец подал заявку 20.10.2026.
- **Остальные источники** — вердикты разведчика от 20.10.2026 в каталоге и [отчёте](../sources/scout-2026-10-20.md). Stack Exchange — `needs_agreement`: AI-обработка только по лицензии. Второй источник болей без ключа — **Lemmy (lemmy.world)**, `allowed`; Bluesky — `allowed`, нужен пароль приложения и способ удалить фрагмент по просьбе автора.

## Решить в спецификации

- **Как хранить сигналы спроса** — ряды чисел по дням (Википедия, Trends, Keyword Planner). Это не посты: варианты — `Evidence` с агрегатом и ссылкой (`kind` для данных) или отдельный журнал метрик. Новая сущность или таблица → миграция. Смена модели данных → ADR.
- **Как сигналы спроса входят в оценку возможности** (`scoreOpportunity`): только кодом и только из данных (§2.13). Веса меняются только вместе с проверкой на примерах.
- **Персональные данные.** У Stack Exchange и Bluesky есть ники, у Bluesky — DID. Не сохранять, вычищать до записи, как у Hacker News.

## Что нужно от владельца

1. **Доступ среды разработки к сайтам условий**, чтобы проверить официальные тексты. Полный список и шаги — в [отчёте разведчика от 20.10.2026](../sources/scout-2026-10-20.md#домены-для-доступа); первые источники:
   - Wikimedia: `meta.wikimedia.org`, `foundation.wikimedia.org`, `doc.wikimedia.org`, `www.mediawiki.org`, `wikimedia.org`;
   - Stack Exchange: `stackoverflow.com`, `stackexchange.com`, `api.stackexchange.com`, `stackapps.com`;
   - Bluesky: `bsky.social`, `bsky.app`, `docs.bsky.app`, `blueskyweb.xyz`, `public.api.bsky.app`;
   - GDELT: `gdeltproject.org`, `www.gdeltproject.org`, `api.gdeltproject.org`;
   - Google: `developers.google.com`, `policies.google.com`;
   - Product Hunt: `www.producthunt.com`, `api.producthunt.com`.
2. **Ключи и входы** — когда до них дойдёт очередь, только в Variables Railway:
   - ключ приложения Stack Exchange (бесплатно, stackapps.com);
   - app password Bluesky;
   - ключ Google Trends после одобрения;
   - токен Google Ads.

## Разведчик источников (D-026)

Новые источники ищет и проверяет разведчик: [`.claude/skills/source-scout/SKILL.md`](../../.claude/skills/source-scout/SKILL.md). Он запускается раз в неделю и по просьбе владельца.

- Читает официальные условия и записывает вердикт в каталог с цитатой.
- Для разрешённых источников пишет подключение с тестами.
- Отчёт — [`docs/sources/`](../sources/README.md): что нужно от владельца (регистрации, ключи) и какие сайты ещё закрыты.
- Решение о доступе остаётся за владельцем — карточка в `/decisions`.
