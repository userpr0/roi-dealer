## Objective

Единая безопасная точка вызова AI — `runTask` — для всех будущих агентов и судей. Она:

- выбирает модель по результатам эталонных прогонов: для массовой работы — самую дешёвую из прошедших, для суждений — самую точную;
- при сбое переходит на модель другого провайдера (Claude, GPT, Gemini);
- проверяет ответ схемой;
- не тратит больше бюджета: $50 в месяц, распределённые по дням, у каждого процесса — своя доля дня;
- останавливается стоп-краном;
- не запускает задачу без проходного прогона на эталонном наборе.

Первая задача закрывает остаточный риск PHASE 05: имена людей в тексте Evidence.

## Business purpose

- PHASE 06–12 (боли, возможности, агенты, судьи) строятся на AI.
- Без лимитов, эталонов и проверки ответа AI либо разорит бюджет, либо принесёт выдуманные данные (§2.5).
- Здесь закладываются правила, по которым будет работать каждая следующая AI-задача.

## Scope

### 1. Задача (`AiTask`)

- `name`, `version` — версия промпта;
- `tier` — `bulk` или `strong`;
- инструкции;
- Zod-схемы входа и выхода;
- `maxOutputTokens`;
- предел стоимости одного вызова (`maxCostMicroUsd`) — резерв перед вызовом;
- доля дневной квоты (`dailyShare`);
- эталонный набор (от 20 примеров) и функция оценки ответа.

### 2. Реестр моделей и маршрутизация

- **Реестр — в коде:**
  - провайдер, ID, уровень;
  - цена in/out в микродолларах за 1M токенов;
  - контекст, поддержка структурированного ответа;
  - дата и источник проверки цены.
- **Стартовые модели:**
  - `bulk` — `claude-haiku-5-5`, `gemini-3.1-flash-lite`, `gpt-5.4-mini`;
  - `strong` — `claude-opus-5-5`.
- **Маршрут (D-021):**
  1. Кандидаты — модели уровня задачи, у которых есть ключ провайдера, которые подтверждены списком моделей при запуске и имеют проходной отчёт evals.
  2. Порядок задают отчёты: `bulk` — по стоимости прогона, `strong` — по среднему метрик. При равенстве решает порядок реестра.
  3. Вторым идёт другой провайдер.
  4. При сбое — следующая модель.
- **Классы сбоев:**

  | Сбой                                                                                        | Что делается дальше                           |
  | ------------------------------------------------------------------------------------------- | --------------------------------------------- |
  | `rate_limited`, `timeout`, `server_error`, `invalid_output`, `refusal`, `model_unavailable` | Следующая модель                              |
  | `auth`, `bad_request`                                                                       | Следующая модель; в лог — ошибка конфигурации |
  | `budget`, `paused`                                                                          | Ни одного вызова                              |

### 3. `runTask(task, input, context)`

1. Вход проверяется схемой.
2. **Preflight:**
   - стоп-кран;
   - есть ли разрешённая модель;
   - перед каждой попыткой — бюджет с резервом стоимости вызова (раздел 5).
3. Вызов адаптера: официальный SDK, таймаут, без автоповторов SDK — повтор делает маршрутизатор.
4. Ответ проверяется схемой.
5. Запись в `ai_calls`.

Результат — данные или `AiTaskError` с кодом и списком попыток. Ключи и тексты в лог не попадают.

### 4. Журнал `ai_calls` — миграция `0006_ai_runtime`

- **Поля:**
  - время, задача, версия, назначение (`task` / `eval`);
  - провайдер (`anthropic`, `openai`, `google`), модель;
  - токены in/out, стоимость в микродолларах, задержка;
  - итог, класс сбоя, актор, `correlation_id`.
- **Только добавление**, не сущность — как `access_log`.
- **Суммы за период, по задаче и назначению** — основа бюджета и строк в пульте.

### 5. Бюджет и учёт расходов (D-007, D-021)

- **Месяц:** не больше $50.
- **Квота дня:** остаток месяца на начало дня, делённый на оставшиеся дни месяца, но не больше $20. Свежий месяц из 30 дней даёт ≈ $1.67 в день; что не потрачено сегодня, достаётся следующим дням.
- **Доля процесса:** задача тратит за день не больше `dailyShare` от квоты, все evals вместе — не больше 20 %. Сумма долей ≤ 1.
- **Резерв:** каждая проверка резервирует `maxCostMicroUsd` — худшую стоимость вызова на любой модели уровня.
- **Расчёт токенов** по процессам — в [ADR-0006](../ADR/0006-ai-providers-and-runtime.md#расчёт-токенов-на-день).
- **`CostEntry`:** раз в сутки (worker) за прошедший день UTC система пишет `CostEntry` категории `ai` — идемпотентно, ключ `ai-cost-<дата>`. Сумма округляется вверх до цента. Дневной предел $20 держит запись ниже порога одобрения D-006.

### 6. Evals

- `evaluate(task, model)` — прогон эталонного набора через выбранную модель.
- Каждый вызов идёт с назначением `eval` и учитывается в бюджете.
- Отчёт сохраняется как `KnowledgeAsset` (`kind: knowledge`):
  - теги `eval`, `task-<имя>`, `v-<версия>`, `model-<id>`, `passed` / `failed`;
  - метрики и стоимость прогона в теле — по ним строится маршрут.
- **Gate:** `runTask` не использует модель без проходного отчёта для этой версии задачи.
- Worker при запуске прогоняет evals там, где отчёта нет и есть ключ, в пределах доли evals. Новая версия промпта или новая модель — новый прогон.
- **CI проверяет:**
  - у каждой задачи ≥ 20 примеров;
  - функция оценки детерминирована;
  - эталонные ответы проходят собственную оценку;
  - сумма долей ≤ 1;
  - резерв покрывает худший вызов.

### 7. Первая задача — `redact-names`

- AI получает текст и возвращает **список имён людей**. Заменяет их код, а не AI (§2.3): каждое имя превращается в `[name]`.
- **Порог:** полнота ≥ 0.9, точность ≥ 0.8. Названия продуктов и компаний не считаются именами.
- **Доля дня:** 10 %.
- **В сборе Evidence:** после очистки правилами, если AI доступен. Если AI недоступен или квота исчерпана, остаётся очистка правилами (как в PHASE 05). После первого сбоя загрузка продолжается без AI.

### 8. Worker и пульт

- **Worker:**
  - переменные `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY` (необязательные);
  - при запуске и раз в сутки — проверка моделей;
  - каждый час — недостающие evals и запись расходов за вчера.
- **`/status`:** «🤖 AI сегодня: $X из $Y · за месяц $Z из $50» и последний успешный вызов Claude / GPT / Gemini.
- **Дайджест:** траты AI за сутки, число вызовов и ошибок.
- **Стоп-кран** останавливает и AI.

## Out of scope

- **Агенты и судьи** — PHASE 10–11.
- **Боли и сигналы** — PHASE 06.
- **Batch API и кэш промптов:** объёмы пока малы. Вернуться, когда расходы станут заметны.
- **Сильные модели OpenAI и Google** — с первой `strong`-задачей.
- **Поиск Google в Gemini** — с агентом контекста рынка (PHASE 10), после проверки условий.
- **Изменение лимитов и долей из пульта** — PHASE 16.

## Acceptance criteria

1. Без ключей и без проходного отчёта evals нет ни одного вызова. Задача отвечает «AI недоступен», сбор Evidence работает правилами.
2. На фейковых серверах Anthropic, OpenAI и Gemini:
   - успешный структурированный ответ;
   - каждый класс сбоя одинаково распознаётся тремя адаптерами;
   - сбой основной модели → модель другого провайдера;
   - все модели упали → `AiTaskError` со списком попыток.
3. Порядок моделей задают evals: если модель дешевле на эталоне, она идёт первой.
4. Бюджет:
   - при исчерпании месяца, квоты дня или доли задачи вызова нет (сбой `budget`), другие задачи работают в своих долях;
   - квота дня — остаток месяца на оставшиеся дни;
   - стоп-кран → вызова нет.
5. Каждая попытка в `ai_calls` со стоимостью по реестру. Ежедневная `CostEntry` идемпотентна.
6. Evals:
   - отчёт сохраняется как `KnowledgeAsset`;
   - модель с проваленным отчётом не используется;
   - новая версия задачи требует нового прогона.
7. `redact-names` вычищает имена в Evidence (фейковый провайдер); эталонный набор проходит собственную оценку.
8. Процесс worker с тремя фейковыми провайдерами:
   - проверяет модели;
   - прогоняет evals;
   - собирает Evidence с вычисткой имён;
   - ключи не попадают в логи.
9. typecheck, lint, format, тесты, build, оба образа — зелёные.

## Действия владельца после вливания

1. **Создать API-ключи** — подробно в [инструкции worker](../deploy/worker.md#ai-ключи-phase-09):
   - console.anthropic.com;
   - platform.openai.com;
   - aistudio.google.com — с включённой оплатой.
2. **Выставить лимиты** в кабинетах, в сумме ≤ $50/мес.
3. **Railway** → `worker` → **Variables**: `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`. В чат не присылать.
4. **Проверить:**
   - логи worker — `ai models verified`, `ai eval passed`;
   - `/status` — строка AI.
