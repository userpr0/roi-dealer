## Implemented

- **`runTask(task, input, context)`** — единая точка вызова AI, `@roi-dealer/ai-runtime`:
  1. вход проверяется схемой задачи;
  2. стоп-кран;
  3. модели с проходным отчётом evals — в порядке по evals;
  4. бюджет с резервом перед каждой попыткой;
  5. вызов;
  6. ответ проверяется схемой;
  7. запись в `ai_calls`.

  При сбое пробуется модель другого провайдера. Если упали все — `AiTaskError` со списком попыток.

- **Три провайдера (D-021)** — адаптеры официальных SDK:
  - Claude — `@anthropic-ai/sdk`;
  - GPT — `openai`, Responses API, `store: false`;
  - Gemini — `@google/genai`.

  Автоповторы SDK выключены. Ответ разбирает адаптер, поэтому токены невалидного ответа тоже учитываются. Классы сбоев: `rate_limited`, `timeout`, `server_error`, `invalid_output`, `refusal`, `model_unavailable`, `auth`, `bad_request`.

- **Реестр моделей:**
  - `bulk` — `claude-haiku-5-5`, `gemini-3.1-flash-lite`, `gpt-5.4-mini`;
  - `strong` — `claude-opus-5-5`.

  У каждой модели цены в микродолларах, источник и дата проверки цены. Worker подтверждает модели списками провайдеров при запуске и раз в сутки.

- **Кто что делает (D-021):** порядок моделей для задачи задают её отчёты evals:
  - массовая работа — самая дешёвая модель из прошедших эталон;
  - суждения — самая точная;
  - второй идёт другой провайдер.

- **Бюджет на весь день (D-007, D-021):**
  - месяц — не больше $50;
  - квота дня — остаток месяца на оставшиеся дни, не больше $20;
  - доля дня каждой задачи (`dailyShare`) и 20 % на evals;
  - резерв худшей стоимости вызова.

  Расчёт токенов по процессам — в [ADR-0006](../ADR/0006-ai-providers-and-runtime.md#расчёт-токенов-на-день).

- **Evals:**
  - отчёт прогона — `KnowledgeAsset` с тегами и метриками;
  - модель без проходного отчёта для версии задачи не используется;
  - worker сам прогоняет недостающие evals.

- **Деньги в учёте:** журнал `ai_calls` (миграция `0006`) и ежедневная `CostEntry` категории `ai` (ключ `ai-cost-<дата>`, сумма вверх до цента).
- **Первая задача `redact-names`:**
  - 24 эталонных примера;
  - точность ≥ 0.8, полнота ≥ 0.9;
  - AI предлагает имена, код заменяет их на `[name]` и пропускает выдуманные.

  В сборе Evidence задача работает после очистки правилами. Без AI остаются правила; после первого сбоя загрузка продолжается без AI.

- **Worker:**
  - ключи `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY` (необязательные), лимиты;
  - обслуживание раз в час: модели, evals, расходы за вчера.
- **Пульт:**
  - `/status` — «🤖 AI сегодня: $X из $Y · за месяц $Z из $50» и последний успешный вызов Claude / GPT / Gemini;
  - дайджест — траты за сутки, вызовы, ошибки.
- **Документы:**
  - ADR-0006 (три провайдера, распределение ролей, расчёт токенов);
  - D-021;
  - инструкция по ключам в [worker.md](../deploy/worker.md#ai-ключи-phase-09);
  - runbook утечки ключа AI.

## Security implications

- **Ключи — секреты:**
  - только в Variables сервиса worker;
  - в коде, логах и БД их нет (тест проверяет логи и `ai_calls`);
  - утечка — [runbook](../runbooks/secret-leak.md#ключи-ai-claude-gpt-gemini).
- **Провайдерам уходят только цитаты Evidence** после очистки правилами: публичные посты без контактов. Промпты и ответы не хранятся.
- **Ключ Gemini — только с оплатой:** на бесплатном уровне Google может использовать запросы.
- **AI ничего не решает (§2.3).** Он возвращает список имён, а заменяет их код — только то, что действительно есть в тексте.
- **Стоп-кран** останавливает все вызовы и evals.

## Cost implications

- **Лимит AI — $50 в месяц** (D-007), в коде:
  - квота дня — остаток месяца на оставшиеся дни (≈ $1.6), не больше $20;
  - каждый процесс в пределах своей доли.

  У провайдеров — свои лимиты, в сумме ≤ $50.

- **Вычистка имён:**
  - ≈ $0.0001 за пост на Haiku;
  - обычный день — меньше $0.01, худший — $0.07.
- **Первый запуск evals:** около $0.03.
- **Ежедневная запись `CostEntry`** не превышает $20 и не требует одобрения (D-006).

## Known limitations

- **API провайдеров недоступны из облачной среды разработки.** Адаптеры проверены на фейковых серверах в формате ответов официальных SDK. Первые настоящие вызовы — после ключей в Railway.
- **Цены и ID моделей:**
  - Anthropic — из справочника Claude API;
  - Google — со страницы цен Gemini API;
  - OpenAI — из сторонних сводок.

  Недоступная модель отсекается проверкой списка, но цену проверить так нельзя.

- **`/status` показывает лимит $50 по умолчанию.** Если в worker лимит понижен переменной, бот этого не знает.
- **Нет пакетной обработки и кэша промптов:** объёмы пока малы.

## Architecture deviations

- Нет. AI вызывается только через `@roi-dealer/ai-runtime`. Домен знает лишь лимиты D-007 и квоту дня, но не провайдеров.
- **Gemini — третий провайдер** по решению владельца D-021, внесён в ADR-0006 до вливания.

## Scope decisions

- **Порядок моделей — по evals, а не вручную:** измерение на наших данных вместо мнения. Новая модель сама займёт своё место после прогона.
- **Сильные модели OpenAI и Google** — с первой `strong`-задачей. Поиск Google в Gemini — с агентом контекста рынка (PHASE 10), после проверки условий.
- **Доли дня** заданы для существующих процессов (вычистка — 10 %, evals — 20 %). План на следующие фазы — в ADR-0006.

## Business hypothesis enabled by this phase

Следующие фазы — боли, агенты, судьи — получают AI с проверкой качества и ценой под контролем. Системе хватает бюджета на каждый день месяца, а владелец видит в `/status`, сколько потрачено.
