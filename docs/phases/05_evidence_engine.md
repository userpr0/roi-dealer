# PHASE 05 — Evidence Engine

> **Основание:** playbook §7 (PHASE 05 — sources, snapshots, evidence, claims, provenance, trust) и §11 (collect source data → create Evidence); конституция §2.5 (Evidence First), §2.20 (паттерн, а не копия), §2.21 (только разрешённый доступ), §2.6 (ограниченные автоматизации и стоп-кран); D-008 (США и англоязычные рынки Tier-1); D-014 п.5–6 ([требования](05_evidence_engine.plan.md)); D-019 (одобрение фазы), D-020 (план до Уровня 2).
> Спецификацию составил Claude (D-019). **Отчёт:** [05_evidence_engine.report.md](05_evidence_engine.report.md).

## Objective

Система сама и законно собирает рыночные данные:

1. Источник подключается только после записи в каталоге с проверенными условиями использования и после одобрения владельца в `/decisions`.
2. Worker по расписанию забирает новые материалы через официальный API.
3. Из текста до сохранения вычищаются контакты и идентификаторы людей.
4. Каждое доказательство (Evidence) хранит происхождение: источник → загрузка (снимок) → ссылка на оригинал.

## Business purpose

- **Evidence — сырьё всего цикла ROI CORE.** Из него строятся:
  - сигналы и боли (PHASE 06);
  - возможности (PHASE 07);
  - знания (PHASE 08);
  - оценки судей (PHASE 11).

  Без данных следующие фазы не к чему применять.

- **Нарушение правил площадки** (скрейпинг, обход лимитов) и **утечка персональных данных** — главные риски этой фазы. Их закрывают каталог, одобрение владельца и очистка данных до записи.

## Scope

### 1. Каталог источников — `@roi-dealer/evidence` (новый пакет)

- **Где хранится.** Каталог — в коде (`catalog.ts`): любое изменение проходит через pull request, который вливает владелец.
- **Поля записи:**
  - ключ, название, сайт;
  - **способ доступа** (официальный API / RSS / выгрузка / ручной ввод);
  - **условия использования** (ссылки и вывод проверки);
  - **стоимость**;
  - **лимиты** (включая наш интервал опроса и максимум элементов за запуск);
  - **поля данных**: что отдаёт источник и что мы храним;
  - **риск персональных данных**;
  - **рынки и язык**;
  - **доверие по умолчанию**;
  - **статус проверки**: кто и когда проверил, вердикт.
- **Вердикты:**
  - `allowed` — можно подключать;
  - `needs_agreement` — нужен договор с площадкой;
  - `needs_review` — условия не подтверждены;
  - `rejected` — не подключаем.
- **Коннектор отказывается работать**, если источника нет в каталоге или его вердикт не `allowed`.
- **Проверка октября 2026:**

### 2. Домен

- **`Source.catalogKey`** (необязательный) — запись каталога, по которой подключён источник. Один источник на запись каталога.
- **16-я сущность `SourceSnapshot`** — неизменяемая запись об одной загрузке:
  - источник;
  - время;
  - URL запроса (без секретов);
  - sha256 ответа;
  - число полученных элементов и сохранённых доказательств.

  **Сырой ответ не хранится** (срок хранения 0, минимизация данных). Повторная обработка — новой загрузкой.

- **`Evidence` получает:**
  - `snapshotId` — из какой загрузки;
  - `externalId` — id элемента у источника, для дедупликации.
- **Новое правило домена:** в цитате Evidence нет email и телефонов (`containsContactData`).

### 3. Приватность (D-014 п.6)

`redactPersonalData` до сохранения заменяет:

| Что                                                                                                    | На что      |
| ------------------------------------------------------------------------------------------------------ | ----------- |
| email                                                                                                  | `[email]`   |
| телефоны                                                                                               | `[phone]`   |
| ссылки на профили (HN user, X / Twitter, LinkedIn, Facebook, Instagram, TikTok, Telegram, Reddit user) | `[profile]` |
| `@ники`                                                                                                | `[handle]`  |
| номера вида SSN                                                                                        | `[ssn]`     |
| номера карт (с проверкой Луна)                                                                         | `[card]`    |
| IPv4-адреса                                                                                            | `[ip]`      |

- Автор (`by`) и любые поля профиля не запрашиваются и не сохраняются.
- **Остаточный риск** — имена внутри текста. Их надёжно находит только AI (PHASE 09); это записано в каталоге.
- **Запрос человека на удаление** (CCPA / GDPR) — runbook [`data-deletion-request.md`](../runbooks/data-deletion-request.md).

### 4. Миграция `0005_evidence_engine`

- **Тип сущности:** `entity_type` + `source_snapshot`.
- **`sources`:** `catalog_key` (формат ключа, уникальный).
- **Таблица `source_snapshots`:**
  - только добавление;
  - событие обязательно;
  - `(id, source_id)` уникальны — для составного FK.
- **`evidence`:**
  - `snapshot_id` → FK `(snapshot_id, source_id)`: снимок того же источника;
  - `external_id`, уникальный в пределах источника;
  - CHECK «нет email в цитате».

### 5. Сбор

- **Интерфейс `SourceConnector`.** Коннектор Hacker News:
  - `askstories` → новые id;
  - элементы: заголовок + текст, HTML → текст;
  - удалённые и `dead` пропускаются;
  - цитата до 1 000 символов;
  - не больше 30 элементов за запуск;
  - таймаут на каждый запрос.
- **`collectEvidence`:**
  1. `assertAutomationRunning` — первым шагом (стоп-кран).
  2. Каталог: запись есть и вердикт `allowed`.
  3. Источник `active`.
  4. Личность интеграции `source:<ключ>` активна.
  5. Загрузка → очистка → одна транзакция: снимок + доказательства от актора интеграции с `correlationId`.
- **`ensureConnection` (действует `system`):**
  - нет источника — создаёт его по каталогу;
  - нет личности — запрос доступа `access_grant` в `/decisions`, с условиями источника в тексте;
  - срок запроса истёк — новый запрос;
  - владелец отказал (личность `revoked`) — источник переводится в `retired`.
- **Планировщик:** раз в `EVIDENCE_COLLECT_INTERVAL_MINUTES` (по умолчанию 60), без наложения запусков, ошибки — в лог.

### 6. Worker и деплой

- **`apps/worker`** с `DATABASE_URL` запускает планировщик. Без `DATABASE_URL` работает как раньше (heartbeat).
- **Temporal не подключается:** долгих workflow ещё нет; ADR — при первом (TECH_STACK).
- **`apps/worker/Dockerfile`:**
  - образ с миграциями;
  - Pre-deploy Command — тот же раннер миграций (параллельный запуск с ботом безопасен: блокировка);
  - CI собирает и образ worker.
- **Инструкция владельцу:** [`docs/deploy/worker.md`](../deploy/worker.md).

### 7. Пульт

- **`requestAccess` и `ensureAccessRequest`** в `@roi-dealer/command-center`. Повторный запрос нужен для уже существующей личности, у которой истёк срок запроса.
- **Дайджест:** строка «📚 Новых доказательств за сутки: N», если они были.
- **Журнал:** подряд идущие одинаковые события одного запроса (например, 30 доказательств одной загрузки) сворачиваются в одну строку «×N». Решения владельца не тонут среди данных.

## Out of scope

- **Claims и извлечение смысла** из текста — PHASE 06 и 09 (нужен AI).
- **Остальные источники каталога** — после проверки их условий: каждый — отдельной записью и коннектором.
- **Хранение сырых снимков** (S3) — пока не нужно.
- **Ручной ввод Evidence в пульте** (➕) — PHASE 13.
- **Комментарии HN, поиск по ключевым словам** (Algolia), рынок у Evidence: аудитория HN глобальная англоязычная, рынок не присваивается.
- **Механизм удаления в коде:** описан runbook с аварийной миграцией; автоматизация — при первом запросе.

## Acceptance criteria

1. В каталоге — все кандидаты с вердиктом и датой проверки. Коннектор не работает с источником без записи или без `allowed` (тест).
2. Без одобрения владельца (личность не `active`) ни один запрос к источнику не выполняется (тест).
3. **Стоп-кран:** при паузе ни подключение, ни сбор не выполняются (тест).
4. **Персональные данные вычищены:** email, телефоны, профили, ники, SSN, карты, IP; автор не сохраняется (тесты). Доменное правило и CHECK в БД не пропускают email.
5. Повторный сбор не создаёт дубликатов (тест; уникальность в БД).
6. **Provenance:** у Evidence есть снимок того же источника, у снимка — хеш и время; всё с событиями.
7. Процесс worker с фейковым HN и настоящей БД:
   - запрашивает доступ;
   - после одобрения собирает Evidence;
   - останавливается корректно.
8. typecheck, lint, format, unit + integration, build, оба Docker-образа — зелёные.
