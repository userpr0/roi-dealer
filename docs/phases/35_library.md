# 35 — Библиотека «вертикаль → проект → тема»

> **Статус:** спецификация. Направление одобрено D-040; архитектура — [ADR-0016](../ADR/0016-library-and-own-assets.md), часть 1, ждёт «одобряю ADR-0016».

## Шаги

1. **Миграция `0028_library`:**
   - сущности `verticals`, `projects`, `topics` с событиями;
   - журнал `library_filings` (append-only);
   - уникальность названия внутри родителя.
2. **Домен:**
   - фабрики и переходы `active` ⇄ `archived`;
   - `currentTopic(filings)` — действует последняя запись.
3. **AI-задача `file-library`** (bulk, бесплатная квота):
   - эталонный набор ≥ 20 случаев;
   - код подбирает близкую тему по словам и держит лимиты дерева.
4. **Агент `librarian`** по общему расписанию:
   - раскладывает новые боли, возможности, тесты, объекты и темы `/seek`;
   - каждую версию объекта — один раз.
5. **Пульт:** `/library` — дерево с кнопками; «переложить» и «архивировать» — с подтверждением, через `database.command`.
6. **Дайджест:** строка «новое в библиотеке: N».
7. **Выгрузка** в закрытый репозиторий `userpr0/roi-library` раз в день:
   - пишет `integration:library-export`, ключ `LIBRARY_GITHUB_TOKEN`;
   - только названия, статусы, числа, ссылки.

## Тесты

- **unit:**
  - лимиты дерева, выбор близкой темы, текущая тема по журналу;
  - Markdown выгрузки без персональных данных.
- **integration:**
  - журнал append-only;
  - перенос владельцем;
  - агент раскладывает каждую версию один раз;
  - выгрузка в локальный fake GitHub.

## От владельца

- Создать пустой закрытый репозиторий `roi-library`.
- Выдать fine-grained token: доступ Contents: write только к нему.
- Положить токен в Railway → `worker` → `LIBRARY_GITHUB_TOKEN`. Не в чат.
