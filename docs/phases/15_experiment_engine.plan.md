# PHASE 15 — Experiment Engine: требования владельца

> **Статус:** backlog требований (D-014, пункты 8–9). Реализация — в PHASE 15 (и Release Gate в PHASE 21) после approval владельца; спецификации фаз обязаны включить эти требования.
> **Основание:** playbook §7.1 (Fast Commercial Validation), §7.2 (Public Validation Release Gate), §2.17 outcome-first.

## 1. Честная проверка спроса (D-014 п.8)

Цель — проверить спрос, не обманывая людей и не нарушая правила площадок.

- **Лендинг несуществующего продукта (fake door):** прямо сказано «скоро» или «лист ожидания»; нельзя выдавать продукт за готовый.
- **Предзаказ:** дата поставки, условия и простой возврат денег указаны до оплаты; если продукт не будет сделан, деньги возвращаются.
- **Без выдуманных отзывов, цифр и результатов.** Обещанный результат подтверждается доказательствами (§2.17).
- **Правила рекламных площадок** проверяются до запуска: запрещённые категории, требования к лендингу, формулировки.
- **На каждом лендинге:** политика конфиденциальности, условия, согласие на рассылку (CAN-SPAM, GDPR), контакт для связи.
- **Release Gate (§7.2):** эксперимент с публичным трафиком не запускается, пока эти пункты не отмечены.

## 2. Единая воронка событий (D-014 п.9)

Все эксперименты пишут одинаковые события — иначе их нельзя сравнить.

| Событие          | Смысл                                                               |
| ---------------- | ------------------------------------------------------------------- |
| `impression`     | Показ креатива или объявления                                       |
| `attention`      | Посетитель задержался (например, просмотр ≥ N секунд или прокрутка) |
| `cta_click`      | Нажатие на призыв к действию                                        |
| `activation`     | Первое полезное действие                                            |
| `lead` / `trial` | Заявка, регистрация, пробный период                                 |
| `payment`        | Оплата или предзаказ                                                |
| `product_use`    | Использование продукта                                              |
| `outcome`        | Достигнутый результат для клиента                                   |
| `retention`      | Возврат или повторная покупка                                       |

- Каждое событие несёт `experiment_id`, `hypothesis_id`, канал, UTM-метки и время в UTC.
- Метрика успеха гипотезы (`successMetric`) считается из этих событий детерминированно, в коде или SQL (§7.3).
- Инструмент аналитики выбирается ADR в PHASE 15: предпочтительно с уважением к приватности, без передачи персональных данных третьим лицам без необходимости.

## Критерии готовности (добавить в спецификацию PHASE 15)

1. Эксперимент нельзя перевести в `running`, пока не пройден чек-лист честной проверки.
2. Все эксперименты пишут события одной схемы; отчёт по воронке строится одинаково для любого теста.
