## Implemented

- `@roi-dealer/telegram`: клиент Bot API (`getMe`, `getUpdates`, `sendMessage`, `setMyCommands`) с Zod-валидацией и вырезанием токена из ошибок; long polling с backoff, `retry_after`, обработкой 409 и фатальной остановкой на 401 / 404, подтверждением offset при остановке; маршрутизатор команд только для владельца; notifier.
- `apps/bot`: `/start`, `/status` (здоровье через `HealthRegistry`, версия, окружение, аптайм), `/help`; уведомления о запуске и остановке; меню команд только в чате владельца; shutdown 8 s, таймаут запросов 5 s.
- `apps/bot/Dockerfile` (multi-stage, runtime только `dist` + prod-зависимости, пользователь `node`), `.dockerignore`.
- CI: новый job «Build bot Docker image».
- Скрипты: `pnpm dev:bot`; бот исключён из общего `pnpm dev`, чтобы не конфликтовать с облачным экземпляром.

## Security

- Токен: только переменная окружения; Zod-ошибка без значения; вырезается из текстов ошибок; ключ `*token` редактируется logger; не попадает в образ (`.dockerignore` исключает `.env*`).
- Доступ: только владелец, только личный чат; чужие сообщения без ответа; в логах только `user_id`.
- Bot API только по HTTPS; HTTP разрешён только для localhost.
- Отправка сообщений — plain text (без `parse_mode`), без инъекции разметки.
- Контейнер работает от пользователя `node`, без открытых портов.

## Scope decisions

- Реализовано: только то, что выбрал владелец — бот-пульт с командами на чтение и уведомлениями, облачный Docker-образ.
- Отложено: Mini App с данными и `initData`, команды с изменением состояния, webhook, выбор и настройка конкретного хостинга (аккаунт владельца).

## Business hypothesis enabled by this phase

- Инфраструктурная: владелец управляет системой и получает сигналы с телефона. Основа для human gates (§2.7) и алертов без отдельного интерфейса.

## Authoritative data paths verified

- Нет: бот не читает и не меняет бизнес-данные. `/status` берёт данные из `HealthRegistry` процесса в момент запроса.

## Known limitations

- Живой Telegram из среды разработки недоступен (сетевая политика), поэтому проверка шла на поддельном Bot API. Первый реальный запуск — после деплоя владельцем.
- Один экземпляр на токен (особенность long polling).
- `/status` показывает здоровье только самого бота: другие сервисы в облаке пока не развёрнуты.

## Technical debt

- Нет автоматической проверки «Wait for CI» на стороне хостинга — зависит от провайдера.
- `actions/deploy-pages@v4` предупреждает о Node.js 20 (работает на Node 24); обновить при выходе новой major-версии.
