## Objective

Каждый черновик возможности оценивают шесть независимых судей. У каждой оценки есть балл, обоснование и ссылки на доказательства. Возможность с полной оценкой уходит в очередь решений владельца (PHASE 12).

## Business purpose

- **Решение владельца — по фактам:** вместо одной цифры 0–100 PHASE 07 он видит, где возможность сильна и где слаба: рынок, боль, экономика, сложность сборки, риски, повторное использование.
- **Отсев до денег:** слабые места видны до эксперимента (§2.19) — возможность с высоким риском или без готовности платить не тратит бюджет.
- **Независимость:** каждый критерий — отдельный вызов. Модель не подстраивает одну оценку под другую.

## Scope

### 1. Шесть критериев

Балл 1–5: чем выше, тем лучше для нас. У риска 5 означает «риск низкий».

| Критерий                          | Что оценивает                                                                         | Нужны ссылки на Evidence |
| --------------------------------- | ------------------------------------------------------------------------------------- | ------------------------ |
| Рынок (`market`)                  | Много ли людей с этой проблемой на рынках D-008, можно ли до них дойти, платят ли уже | да                       |
| Боль и ценность (`pain_value`)    | Насколько часто и дорого болит, ищут ли решение                                       | да                       |
| Экономика (`economics`)           | Платят ли за похожее, покрывает ли цена стоимость обслуживания (AI, API, люди)        | да                       |
| Сборка (`buildability`)           | Может ли владелец с AI собрать продаваемый минимум за несколько недель                | нет                      |
| Риск (`risk`)                     | Регулирование, персональные данные, зависимость от платформ                           | нет                      |
| Повторное использование (`reuse`) | Пригодится ли сделанное и узнанное для других возможностей; похожие прошлые случаи    | нет                      |

### 2. AI-задача `judge-opportunity` (strong)

- **Одна задача на все критерии;** критерий и его шкала — во входе. Каждый критерий — отдельный вызов.
- **Вход:**
  - возможность: заголовок, описание, ICP, проблема → изменение → результат, бизнес-модель;
  - факты из БД: сигналы, источники, составляющие оценки PHASE 07;
  - до 6 цитат Evidence с номерами E1…E6;
  - рыночный контекст PHASE 10 (если есть);
  - до 3 похожих прошлых случаев из Company Brain (`similarCases`).
- **Ответ:** балл, обоснование (до 600 символов), номера цитат, до 3 опасений.
- **Эталон:** 24 примера, по 4 на критерий, с ожидаемым диапазоном баллов. Проходит, если:
  - не меньше 75 % баллов попадают в диапазон;
  - у критериев со ссылками не меньше 90 % ответов ссылаются на цитату;
  - не меньше 90 % ответов валидны.
- **Доля дня — 30 %** (оставшийся резерв). Все доли вместе с evals = 100 %.

### 3. Код проверяет ответ (§2.3, §2.5)

- Балл — целое 1–5, иначе `rejected`.
- Обоснование — от 20 символов, иначе `rejected`.
- Номера цитат — только существующие; сохраняются как id Evidence.
- **Без ссылок на Evidence** у критериев «рынок», «боль», «экономика» балл ограничивается двумя: вывод без доказательств не может быть сильным.

### 4. Хранение — миграция `0011_judges`

- **`opportunity_judgements`**, только добавление. Одна строка на возможность × её версию × критерий:
  - итог `judged` / `rejected` / `failed`;
  - балл; подтверждён ли доказательствами;
  - обоснование и опасения — проверенный ответ, нужен карточке решения;
  - id Evidence, версия задачи, актор, `correlation_id`.
- Без отдельной сущности домена: оценка — журнал, решения по ней принимает владелец (PHASE 12).

### 5. Агент судей (`judges`)

- **На общем запуске PHASE 10** (`runAgent`): стоп-кран, доступ в `/decisions`, журнал запусков. Раз в 3 часа, до 2 возможностей за запуск.
- **Берёт черновики:**
  - рыночный контекст уже собран для этой версии;
  - или черновику больше суток (агент рынка выключен или ничего не нашёл).
- **Продолжает с места остановки:** при нехватке квоты оставшиеся критерии оцениваются в следующем запуске.
- **Когда все шесть строк записаны,** возможность переходит `draft → under_review` (`submitOpportunityForReview`) — в очередь решений владельца.

### 6. Оценка судей — код (§2.13)

- **Итог 0–100** — среднее баллов: (балл − 1) / 4 × 100. Считается только при шести оценках.
- **Слабые места** — критерии с баллом ≤ 2.
- Функция в домене: её покажут пульт и карточка решения.

### 7. Модели (D-021, ADR-0006)

- **Сильные модели трёх провайдеров:** Claude Opus 5.5, GPT-5.5, Gemini 3.1 Pro. Задача работает при ключе любого из них; порядок задают evals — самая точная первой, запасная — у другого провайдера.
- **Цены** OpenAI и Google — по сторонним сводкам. Для бюджета взята верхняя из найденных цен (Gemini 3.1 Pro — $2.50 / $15 за 1M токенов).
- **Модель, которой нет в списке провайдера,** не используется.

### 8. Пульт

- **`/opportunities`:** строка «⚖️ Судьи: 72/100 · рынок 4 · боль 5 · экономика 4 · сборка 5 · риск 3 · повтор 3» и слабые места.
- **Статус** «ждёт решения» — у возможностей в `under_review`.

### 9. Worker

`JUDGES_INTERVAL_MS` — по умолчанию 3 часа.

## Out of scope

- **Карточка решения с кнопками** ✅ / ❌ / 🔍 / ⏸ — PHASE 12.
- **Рекомендация «одобрить / отклонить»** — PHASE 12 (Decision Engine).
- **Калибровка судей по итогам экспериментов** — PHASE 15–16.
- **Внешние данные о рынке** — только из разрешённых источников (§2.5).

## Acceptance criteria

1. Каждый из шести критериев оценивается отдельным вызовом. Балл и обоснование проверены кодом; без ссылок у «рынка», «боли» и «экономики» балл не выше 2.
2. Одна версия возможности × критерий записывается один раз. После нехватки квоты агент продолжает с оставшихся критериев.
3. Судьи ждут рыночный контекст версии (или сутки). Когда шесть оценок записаны, возможность — в `under_review`.
4. Итог 0–100 и слабые места считает код; `/opportunities` их показывает.
5. Эталон 24 примера, доля дня 30 %, резерв покрывает худший вызов сильных моделей; все доли с evals ≤ 1.
6. Стоп-кран, доступ и журнал запусков — как у остальных агентов. Тексты Evidence не попадают в логи.
7. typecheck, lint, format, тесты, build, оба образа — зелёные.

## Действия владельца после вливания

`/decisions` → «Доступ: Судьи» → ✅ → **Да**. Первые оценки — когда сильная модель пройдёт эталон: от одного до трёх дней, из доли evals.
