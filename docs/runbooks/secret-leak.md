# Утечка токена или ключа

**Признаки:** токен или ключ оказался в чате, на скриншоте, в коммите, в чужих руках; письмо GitHub «Secret scanning alert»; бот начал отвечать не так, как обычно, или прислал «🟢 запущен», хотя вы ничего не обновляли.

> Главное правило: **утёкший секрет отзывают, а не прячут.** Удалить сообщение или коммит недостаточно: копии остаются в кэше, истории и у тех, кто успел их увидеть.

## Токен бота (`TELEGRAM_BOT_TOKEN`)

### 1. Отозвать старый токен (1 минута)

1. Telegram → **@BotFather** → отправьте `/revoke`.
2. Выберите **основного** бота.
3. BotFather пришлёт **новый токен**. Старый перестаёт работать сразу.
4. Сохраните новый токен в менеджере паролей с пометкой **PROD**, старую запись удалите.

С этого момента бот в Railway не работает: он пытается войти со старым токеном. Это ожидаемо.

### 2. Вписать новый токен в Railway (2 минуты)

1. [railway.com/dashboard](https://railway.com/dashboard) → проект → карточка **@roi-dealer/bot** → вкладка **Variables**.
2. Строка `TELEGRAM_BOT_TOKEN` → **⋮** справа → **Edit** → вставьте новый токен → **✓**.
3. Вверху **Apply 1 change** → **Deploy**.

### 3. Проверить (3 минуты)

- [ ] Через 2–4 минуты карточка в Railway — **Online**.
- [ ] В Telegram пришло **«🟢 ROI Dealer bot запущен»**.
- [ ] `/status` → «🟢 ROI Dealer: ok».
- [ ] В логах Railway (**Deployments** → **View logs**) нет `(401)`.

### 4. Закрыть хвосты

- Если токен был в коммите: GitHub → вкладка **Security** → **Secret scanning** → алерт → **Close as** → **Revoked**. Затем попросите Claude убрать токен из кода через pull request. Историю коммитов переписывать не нужно: токен уже отозван.
- Если токен утёк вместе с `.env` с ПК: проверьте, нет ли на ПК вирусов, и отзовите заодно токен **тестового** бота.
- Напишите Claude, что произошло, — он проверит логи и репозиторий.

## Токен тестового бота

То же самое, но в @BotFather выбирайте **тестового** бота, а новый токен впишите в локальный `.env` на ПК (`TELEGRAM_BOT_TOKEN=…`). В Railway ничего менять не нужно.

## Другие ключи

Для ключей, которые появятся позже (AI-провайдер, источники данных, платежи, реклама), порядок тот же:

1. **Отозвать** ключ в кабинете провайдера (обычно **API keys** → **Revoke** / **Delete**).
2. **Выпустить новый** и сразу выставить лимит расходов в кабинете провайдера (D-014 п.2).
3. **Вписать** новый ключ в переменные Railway → **Deploy**.
4. **Проверить**, что сервис работает, и посмотреть в кабинете провайдера расходы за последние дни: не тратил ли кто-то чужой.

Конкретные шаги для каждого провайдера добавляются в [README](README.md) при его подключении.

## Аккаунт

Если есть подозрение, что кто-то вошёл в ваш аккаунт.

**GitHub**

1. Settings → **Password and authentication** → смените пароль; проверьте, что двухфакторка включена.
2. Settings → **Sessions** → **Revoke** все сеансы, кроме текущего.
3. Settings → **SSH and GPG keys**, **Developer settings → Personal access tokens**, **Applications** → удалите всё незнакомое.
4. Репозиторий → **Settings** → **Collaborators**: нет ли посторонних. **Rules → Rulesets**: правило `Protect main` на месте и **Active**.
5. Репозиторий → **Actions**: нет ли незнакомых запусков.

**Railway**

1. Account Settings → смените способ входа или пароль GitHub (вход в Railway идёт через GitHub).
2. Проект → **Settings** → **Members**: нет ли посторонних. Account → **Tokens**: удалите незнакомые.
3. Проверьте **Variables** бота и отзовите токен бота по шагам выше: если кто-то был в Railway, он мог его видеть.

**Telegram**

1. Настройки → **Устройства** → **Завершить все другие сеансы**.
2. Настройки → **Конфиденциальность** → **Облачный пароль**: смените.
3. Если у постороннего был доступ к Telegram, он мог управлять ботами через @BotFather: отзовите токены обоих ботов.
