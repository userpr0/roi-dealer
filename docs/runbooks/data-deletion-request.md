# Запрос человека на удаление его данных (CCPA / GDPR)

> PHASE 05 (D-014 п.6). Описано до начала сбора данных с рынков США и Европы.
> **Срок ответа:** GDPR — 1 месяц, CCPA — 45 дней. Отвечать нужно и тогда, когда данных не нашлось.

## Что мы храним и чего не храним

| Храним                                                             | Не храним                                                                |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| Короткую цитату поста (до 1 000 символов) с заменёнными контактами | Ник автора, ссылки на профили, email, телефоны, `@ники`, IP, номера карт |
| Ссылку на оригинальный пост, время, источник                       | Сырые ответы источников (только их хеш)                                  |
| Снимок загрузки: время, запрос, хеш, счётчики                      | Данные профиля автора                                                    |

Человек узнаётся по цитате только через ссылку на пост: остаточный риск — его имя в тексте. Поэтому запрос обрабатывается по ссылке на пост или по фрагменту текста.

## Шаги

1. **Получить от человека:**
   - ссылку на пост (например, `https://news.ycombinator.com/item?id=…`) или точный фрагмент текста;
   - подтверждение, что это его пост. Достаточно ответа с того же аккаунта площадки.

   Не просите паспорт или лишние данные.

2. **Остановить новые копии.**
   - Если человек просит не собирать его посты дальше: `/access` → ⏸ у источника на время разбора.
   - Если запрос касается всего источника: `/stop`.
3. **Передать Claude** ссылку или фрагмент — без данных самого человека, кроме нужного для поиска. Claude:
   1. найдёт записи: `evidence` по `url` / `external_id` / тексту, их события в `events`, связанные `signals` и `pains` (с PHASE 06);
   2. подготовит **аварийную миграцию** `database/migrations/NNNN_erasure_<дата>.sql`. Она в одной транзакции:
      - отключает триггеры append-only только для этих таблиц, только внутри миграции;
      - заменяет `excerpt` на `[удалено по запросу]` и очищает `url` в `evidence` и в снимках этих записей в `events.payload`;
      - заменяет цитату из этого поста в `signals.summary`, `pains.description` и `opportunities.value_proof` (и в их снимках в `events.payload`) на `[удалено по запросу]`. Строки `signal_extractions` и `opportunity_assessments` текста не содержат и остаются;
      - добавляет запись о факте удаления: дата, тип запроса, число записей, без данных человека;
   3. откроет PR. Вы вливаете — миграция применяется при деплое (Pre-deploy Command).
4. **Проверить:** `/journal` и выборка по ссылке больше не показывают текст. Claude присылает подтверждение.
5. **Ответить человеку:** что удалено и когда; что новые копии не собираются (если источник остаётся подключённым, его посты по этой ссылке будут пропускаться — Claude добавит id в исключения коннектора).
6. Вернуть доступ источнику (`/access` → ▶️), если ставили паузу.

## Почему так

- **История в ROI Dealer неизменяема** (§2.2): обычной командой её не исправить. Аварийная миграция — единственный путь, и она:
  - проходит через PR, который вливает владелец;
  - видна в истории репозитория;
  - сама оставляет след.
- **Механизм в коде** (кнопка, отдельный сервис) появится при первом реальном запросе, если такие запросы станут повторяться (Feature Kill Gate).
