## 3. Путь к рабочему состоянию

Этапы идут в порядке playbook. Внутри каждой фазы — минимальный объём (Feature Kill Gate, §2.15): сначала один рынок (США) и один-два источника данных, расширение — после первых результатов.

### Этап A — запустить пульт (сейчас, действие владельца)

- Развернуть бота в облаке по [инструкции](deploy/telegram-bot.md) (Railway, ~$5/мес) → «🟢 бот запущен», `/status`.

### Этап B — пульт с данными → **Уровень 1**

| Фаза                                                   | Что делаем                                                                                                                         | Что вы увидите                     |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| 02 PostgreSQL Foundation                               | Таблицы и миграции для 13 сущностей, репозитории, optimistic locking; PostgreSQL в облаке, резервные копии                         | Данные не теряются при перезапуске |
| 03 Event History                                       | Append-only журнал событий, аудит, идемпотентность                                                                                 | Основа для журнала и истории       |
| 13b Одобрения и стоп-кран (ранний шаг PHASE 13, D-002) | Карточки одобрения с кнопками ✅ / ❌ / 🔍 / ⏸, стоп-кран, журнал и история за день / неделю / месяц, дайджест 10:00 `Europe/Kyiv` | Управление системой с телефона     |

Инфраструктура этапа: api + worker + бот + PostgreSQL в облаке — в пределах лимита $20/мес (D-007).

### Ориентир по объёму

Одна фаза ≈ одна рабочая сессия, как PHASE 00 или 01. Этап B — около 3 сессий, до Уровня 2 — около 15, до Уровня 3 — около 20. Это ориентир, а не обещание: объём уточняется в спецификации каждой фазы.

## 5. Главные риски и как они закрыты

| Риск                                       | Защита                                                                                        |
| ------------------------------------------ | --------------------------------------------------------------------------------------------- |
| Разрастание объёма, «идеальный продукт»    | Feature Kill Gate, минимальные фазы, один рынок на старте                                     |
| Неконтролируемые расходы на AI и рекламу   | Порог $20, лимиты D-007, stop-loss, стоп-кран                                                 |
| AI принимает решения сам                   | В домене решения закреплены за владельцем; AI только предлагает                               |
| Утечка токенов и ключей                    | Секреты только в переменных хостинга; редактирование в логах; ничего секретного в репозитории |
| Выдуманные AI факты                        | Evidence first; ответы о цифрах только из БД (§2.13, §7.3)                                    |
| Нарушение правил площадок при сборе данных | Только официальные API и разрешённые коннекторы                                               |
