# ADR-0008: Данные Mini App — через `api` с проверкой подписи Telegram

- **Status:** Accepted
- **Date:** 2026-10-19
- **Approved by:** владелец, D-020 (план до Уровня 2). Решение уже записано в TECH_STACK («Telegram Mini App SDK, `initData` на api — PHASE 13») и в последствиях ADR-0002. Стек не меняется, новых зависимостей нет. Сервис `api` в Railway укладывается в лимит инфраструктуры $20 в месяц (D-007) — остановка не требуется.

## Context

- **Mini App публичен.** Она лежит на GitHub Pages (ADR-0002): страницу и сборку может открыть любой, поэтому секретов в сборке быть не может.
- **Данные пульта — только владельцу:**
  - экономика;
  - тесты;
  - очередь решений.
- **Подпись Telegram.** Telegram передаёт Mini App подписанную строку `initData`. Подпись — HMAC-SHA256 с ключом из токена бота. Проверить её может только тот, у кого есть токен, то есть сервер.
- **Доступ к PostgreSQL** — только через `@roi-dealer/database` (CLAUDE.md). У браузера доступа к базе нет.
- **Есть `apps/api`** (PHASE 00, `/health`). Он уже собирается, тестируется и читает `DATABASE_URL`.

## Decision

1. **`GET /api/panel` в `apps/api`** отдаёт снимок пульта (`panelSnapshot` из `@roi-dealer/command-center`):
   - только чтение;
   - те же числа и подписи, что в боте.
2. **Авторизация** — заголовок `Authorization: tma <initData>`. Проверка (`verifyInitData` в `@roi-dealer/telegram`):
   - HMAC по алгоритму Telegram, сравнение в постоянное время;
   - `auth_date` не старше 24 часов;
   - из `user` берётся только `id`.

   Ответы:
   - нет подписи, она чужая или устарела → `401`;
   - подписано, но не владельцем (`TELEGRAM_OWNER_USER_ID`) → `403` и запись отказа в журнале доступа — не чаще раза в 10 минут на аккаунт, как в боте;
   - просмотр владельца → в журнал доступа (канал `telegram`, право `status.read`, корреляция `miniapp-<id>`).

3. **CORS** — только для origin Mini App (`MINIAPP_ORIGINS`, по умолчанию `https://userpr0.github.io`). Preflight `OPTIONS` разрешает только `GET` и заголовок `authorization`. Cookies не используются.
4. **Токен бота в `api`** нужен только для проверки подписи. `api` не вызывает Bot API. В логи не попадают ни токен, ни `initData`, ни заголовок `authorization`.
5. **Адрес `api` в сборке Mini App** — `VITE_API_URL` из переменной репозитория `MINIAPP_API_URL`. Это не секрет. Без него Mini App пишет, что данные не подключены.
6. **Изменения из Mini App не принимаются.** Решения остаются кнопками в боте: подтверждение, идемпотентная команда (D-017).

## Alternatives

| Вариант                                                    | Плюсы                                                        | Минусы                                                                                            | Почему не выбран                                              |
| ---------------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `api` + проверка `initData` (выбрано)                      | Стандарт Telegram; без паролей и cookies; данные не в сборке | Ещё один сервис в Railway                                                                         | —                                                             |
| HTTP-сервер внутри процесса бота                           | Без нового сервиса                                           | Бот работает long polling без публичного адреса; смешение ролей процесса, сбой HTTP задевает бота | Тонкие `apps/*` с одной ролью (SYSTEM_ARCHITECTURE)           |
| Статичный снимок в сборке Mini App (CI пишет JSON)         | Без сервера                                                  | Сборка публична — данные увидит любой; устаревает между сборками                                  | Нарушает ADR-0002: данные только после проверки подписи       |
| Пароль или токен владельца в Mini App                      | Просто                                                       | Секрет в публичной сборке или в localStorage; вводить вручную                                     | Небезопасно и неудобно; подпись Telegram уже есть             |
| Проверка подписи Ed25519 (`signature`, для третьих сторон) | Не нужен токен бота                                          | Нужен публичный ключ Telegram и библиотека; токен у нас и так есть                                | Лишняя зависимость; HMAC — основной способ для владельца бота |

## Consequences

- **Плюсы:**
  - пульт в Telegram с данными без единого секрета в сборке;
  - каждый просмотр и каждая чужая попытка — в журнале доступа;
  - снимок собирается теми же функциями, что и ответы бота, поэтому цифры совпадают.
- **Минусы:**
  - ещё один сервис в Railway (несколько долларов в месяц в пределах $20). Счёт владелец вносит через `/cost`;
  - строка `initData`, утёкшая вместе с устройством владельца, действует до 24 часов. Только на чтение.
- **Дальше:**
  - сбор событий воронки со своих страниц (`tracker`, ADR-0007) — тоже в `apps/api`, отдельным эндпоинтом с ограничением частоты (PHASE 19);
  - если `api` не развёрнут, бот работает полностью — Mini App просто пишет, что данные не подключены.

## Rollback

1. Удалить сервис `api` в Railway и переменную `MINIAPP_API_URL`. Mini App снова покажет, что данные не подключены.
2. Код `GET /api/panel` можно оставить: без `TELEGRAM_BOT_TOKEN` маршрут отвечает `503`.

Данные не затрагиваются: `api` только читает.
