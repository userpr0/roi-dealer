# ADR-0016: Библиотека «вертикаль → проект → тема» и продвижение своих объектов недвижимости

- **Status:** Proposed
- **Date:** 2026-11-12
- **Approved by:** — (направления одобрены D-040; архитектура ждёт «одобряю ADR-0016»)

## Context

D-040: владелец хочет:

1. **Библиотеку.** Всё, что делает система, разложено по вертикалям, проектам и темам, и раскладывает система сама. Владелец и Claude читают библиотеку как папки.
2. **Пилот своих объектов недвижимости** в Украине, сначала Киевская область (Тетиев): страницы объектов, заявки, контент, учёт каналов.

Сейчас ни для того, ни для другого нет моделей данных:

- **Объекты разбросаны.** Боли, возможности, тесты и заявки живут в своих таблицах, общей группировки нет.
- **Страницы только английские.** Их проверяет `checkLanding`, а форма заявки привязана к запущенному тесту возможности: CRM, фаза 20.
- **Заявка — только email.** В Украине по недвижимости звонят: нужен телефон.
- **Рынки D-008** — США, GB, CA, AU.

Это смена модели данных, новый рынок и новый вид персональных данных — поэтому нужен ADR.

## Decision

### Часть 1. Библиотека (фаза 35)

1. **Три сущности:** `Vertical` → `Project` → `Topic`.
   - Версии и события — как у всех сущностей.
   - Название уникально внутри родителя.
   - Статусы: `active`, `archived`.
2. **Журнал `library_filings`** (append-only): объект системы → тема.
   - Поля: `object_type`, `object_id`, `topic_id`, кто положил (`agent:librarian` или `owner`), когда.
   - Действует последняя запись. «Переложить» — новая запись владельца, старые не меняются.
3. **Раскладывает AI-задача `file-library`** — агент `librarian` по общему расписанию.
   - **Вход:** название и краткое описание объекта без персональных данных, текущее дерево, последние 20 переносов владельца как примеры.
   - **Выход:** существующая тема или новые названия (вертикаль, проект, тема).
   - **Код применяет ответ:**
     - сначала ищет близкую существующую тему по словам, как `closestPains`, чтобы не плодить дубли;
     - новые узлы создаёт как `agent:librarian`;
     - держит лимиты: до 20 вертикалей, до 50 проектов в вертикали, до 200 тем в проекте.
   - Задача `bulk` без `privateInput`, может работать на бесплатной квоте Gemini. Эталонный набор ≥ 20 случаев.
4. **Владелец:**
   - `/library` — дерево с кнопками;
   - «переложить» — подтверждение и `database.command`;
   - «архивировать».
   - Подтверждать раскладку не нужно: это не решение о деньгах, тестах или публикации.
5. **Дайджест:** строка «новое в библиотеке: N».
6. **Выгрузка для чтения:** раз в день Markdown-дерево `вертикаль/проект/тема.md` идёт в отдельный закрытый репозиторий GitHub `userpr0/roi-library`.
   - Пишет только `integration:library-export`: стоп-кран, активная личность, ключ `LIBRARY_GITHUB_TOKEN` — fine-grained, доступ Contents: write только к этому репозиторию.
   - В выгрузке только названия, статусы, числа и ссылки на объекты пульта. Никогда — контакты, тексты заявок, ключи.
   - Claude читает выгрузку в начале сессии, владелец — на GitHub.

### Часть 2. Свои объекты (фаза 36)

7. **Рынок `UA` — только для своих активов владельца** (D-040). Поиск возможностей, боли и тесты остаются на рынках D-008.
8. **Сущность `Property`.**
   - **Поля:**
     - вид: квартира, дом, коммерция, земля;
     - сделка: продажа или аренда;
     - область, населённый пункт, улица без номера дома;
     - площадь, комнаты, этаж, участок;
     - коммуникации, цена в центах USD, условия аренды;
     - факты, честные минусы, предложение владельца.
   - **Статусы:** `draft` → `listed` → `under_offer` → `closed` | `withdrawn`.
   - Создаёт и меняет только владелец: `/property` — вставленная анкета → разбор → карточка → подтверждение.
   - Каждый объект сам попадает в библиотеку: «Недвижимость» → проект по населённому пункту → тема — объект.
9. **Фото объекта.**
   - Владелец присылает в бот. Система берёт из Telegram готовый размер до 1280 px.
   - Хранятся в `property_photos` в PostgreSQL: до 15 фото, до 400 КБ каждое. Без нового хранилища и без новой библиотеки обработки изображений.
   - Видео-обходы остаются в Google Drive и идут в Gen_Content.
10. **Страница объекта** — `go.roidealer.com/o/<slug>`, на украинском.
    - Рендер `renderPropertyPage` — как `renderLanding`: статический HTML, всё экранировано, без скриптов и внешних ресурсов, `PAGE_SECURITY_HEADERS`. Фото отдаёт `apps/api`.
    - Страница живёт, пока объект в статусе `listed` или `under_offer`; после — 410.
    - Отдельная политика конфиденциальности на украинском.
11. **Метка канала** `?c=` из фиксированного списка: `olx`, `domria`, `fb`, `tg`, `viber`, `ig`, `tt`, `other`.
    - Счётчики в журнале `property_funnel` (append-only): `view` и `lead` пишет сайт; `call`, `showing`, `deal` — владелец кнопками.
    - Адресов, user agent и cookies не храним.
12. **Заявка с телефоном.**
    - Форма: телефон (обязательно), имя (необязательно), удобный способ связи (звонок, Telegram или Viber), согласие, поле-ловушка, лимиты, стоп-кран.
    - Пишет только `integration:site`.
    - Контакты лежат только в `property_contacts`: без событий, удаляются по-настоящему — при закрытии объекта, по `/forget` и через 180 дней.
    - Свободного текста в заявке нет.
    - Уведомление владельцу — без телефона. Телефон видит только владелец, по кнопке «показать контакт» в своём чате. Это узкое исключение из правила «не отправлять контакты в уведомлениях»: чтобы перезвонить. В логах контакта нет никогда.
13. **AI-задача `write-property-pack`** (украинский, `privateInput: false` — в ней только факты объекта).
    - **Что пишет:**
      - объявления OLX и DOM.RIA;
      - пост для Facebook, Telegram и Viber;
      - текст КП;
      - сценарий видео-обхода;
      - вопросы и возражения с ответами;
      - для коммерции — 2–3 идеи бизнеса.
    - **Проверка `checkPropertyPack`:**
      - каждое число есть в фактах или стоит в блоке с пометкой «оцінка»;
      - нет ссылок и телефонов — контакт и ссылку ставит код;
      - нет «гарантовано», «останній шанс», «терміново», если владелец сам этого не отметил.
    - Эталонный набор ≥ 20 случаев. Тексты пакета — черновик: владелец одобряет на карточке, публикует вручную.
14. **Расходы пилота** — в общих леджерах. Реклама — только через одобренный запрос `spend` (D-007).

## Alternatives

| Вариант                                  | Плюсы              | Минусы                                                                                   | Почему не выбран                                     |
| ---------------------------------------- | ------------------ | ---------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| Библиотека как теги на каждой сущности   | Нет новых таблиц   | Миграция всех таблиц, нет истории переносов                                              | Журнал раскладки проще и не трогает старые таблицы   |
| Выгрузка в Google Drive                  | Привычно владельцу | Нужен OAuth сервиса к Drive; диффы и история хуже                                        | GitHub даёт историю изменений и прямое чтение Claude |
| Объект как тест возможности (фазы 14–20) | Готовая воронка    | Нет боли и гипотез; честная проверка и бюджет теста не подходят к продаже своего объекта | Своя простая воронка честнее и короче                |
| Фото в облачном хранилище (R2)           | Масштаб            | Новый сервис и ключи                                                                     | 15 фото по 400 КБ на объект помещаются в PostgreSQL  |
| Заявка через email, как в CRM            | Готовый код        | Покупатели в Украине звонят                                                              | Телефон с удалением по-настоящему                    |

## Consequences

- **Плюсы:**
  - владелец и Claude видят всё по папкам;
  - первые реальные заявки и сделки проходят через систему;
  - каналы измеряются кодом.
- **Новые персональные данные** — телефоны: отдельная таблица, удаление по-настоящему, без логов. Политика конфиденциальности на украинском.
- **Новая внешняя запись** — GitHub `roi-library`: узкий ключ, только выгрузка без персональных данных.
- **Размер базы:** фото — несколько МБ на объект.

## Rollback

- **Библиотека:** выключить агента `librarian` и выгрузку. Таблицы остаются для истории, на остальную систему не влияют.
- **Объекты:** перевести их в `withdrawn` — страницы отдают 410, контакты удаляются, а `property_funnel` остаётся для итогов.
