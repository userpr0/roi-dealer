# ADR-0010: Хостинг — сервер Hetzner вместо Railway

- **Status:** Accepted
- **Date:** 2026-10-21
- **Approved by:** владелец, D-027 («переводим все на hetzner»). Новых npm-зависимостей нет. Цена — около €5–6 в месяц с ежедневными копиями, в пределах инфраструктурного лимита D-007 ($20).

## Context

- **Railway** с 20.10.2026 17:03 UTC остановил новые сборки для всех проектов, с 21.10 утра недоступны и панель, и API (status.railway.com, Major Outage). Работающие сервисы продолжали работать, но обновления не выходили: два влитых PR (#12, #13) не развернулись, а владелец не мог ни посмотреть логи, ни перезапустить сервис.
- **Ежедневные копии базы** в Railway есть только на тарифе Pro ($20 в месяц) — дороже лимита D-007 вместе с остальным.
- **Владелец работает с телефона** и не пользуется SSH. Переезд и дальнейшая работа не должны требовать терминала.
- Код уже собирается в Docker-образы (`apps/*/Dockerfile`) и проверяется в CI.

## Decision

1. **Один сервер Hetzner Cloud** (Ubuntu 24.04, CX22: 2 vCPU, 4 ГБ) с Docker. На нём `postgres`, `bot`, `worker`, `api` и `caddy` — `infra/hetzner/compose.yaml`.
2. **Образы собирает CI.** После зелёных проверок на `main` CI публикует образы `ghcr.io/userpr0/roi-dealer-{bot,worker,api}` с тегами `main` и короткого коммита (`APP_VERSION`). На сервер попадает только то, что прошло проверки — как «Wait for CI» в Railway.
3. **Сервер обновляется сам.** Таймер systemd раз в 5 минут:
   - забирает `main` из публичного репозитория — compose и скрипты;
   - скачивает новые образы;
   - применяет миграции отдельным одноразовым контейнером `migrate`, до запуска сервисов;
   - перезапускает только изменившиеся сервисы.
     Ключи от GitHub на сервере не нужны: репозиторий и образы публичные.
4. **Установка — одна вставка.** Владелец создаёт сервер в консоли Hetzner и вставляет `infra/hetzner/cloud-init.yaml` со своими ключами в поле «Cloud config». Скрипт `install.sh`:
   - ставит Docker и обновления безопасности;
   - создаёт пароль базы;
   - раскладывает ключи по файлам сервисов — каждый сервис получает только свои переменные;
   - включает файрвол: открыты только 80 и 443;
   - запускает систему.
5. **HTTPS для `api`** — Caddy с сертификатом Let's Encrypt на адрес `<ip>.sslip.io`, который вычисляется из IP сервера. Свой домен не нужен; если он появится, его вписывают в `PUBLIC_HOST`. Бот получает `PUBLIC_API_URL` автоматически.
6. **Копии:**
   - «Backups» Hetzner — ежедневный снимок диска, 7 дней, +20% к цене;
   - каждую ночь `pg_dump` в `/opt/roi-dealer/backups`, хранится 7 дней.
7. **Перезапуск без терминала** — кнопка **Reboot** в консоли Hetzner: контейнеры поднимаются сами (`restart: unless-stopped`).

## Consequences

- **Плюсы:**
  - нет зависимости от сборщика Railway;
  - копии базы входят в лимит;
  - цена ниже;
  - обновления выходят так же сами после зелёного CI.
- **Минусы:**
  - сервер обслуживаем сами: обновления ОС ставятся автоматически (unattended-upgrades), образы — с `main`;
  - один сервер — одна точка отказа; копии позволяют поднять новый за ~15 минут той же вставкой;
  - логи на сервере без SSH не посмотреть — сторож (13c) сообщает о молчании сервиса в Telegram; первая помощь — Reboot.
- **Переезд данных.** Панель Railway недоступна, поэтому база на Hetzner начинается с нуля. Владелец заново одобряет доступы одной кнопкой «Одобрить все доступы». Старая база остаётся в Railway; перенос — отдельной задачей, когда Railway заработает и если в ней будет что-то ценное.
- **Один бот — один сервер.** Перед запуском на Hetzner владелец:
  - останавливает старую автоматику `/stop`, чтобы worker в Railway не тратил AI;
  - получает в @BotFather новый токен — старый перестаёт работать, и два сервера не спорят за сообщения.

## Alternatives

- **Ждать Railway** — неизвестно сколько; копии базы всё равно платные.
- **Fly.io, Render** — те же облачные сборщики с похожим риском и платными копиями базы.
- **Сборка образов на сервере** — без реестра, но медленнее, больше памяти и нужна своя проверка, что коммит прошёл CI.
- **Деплой из GitHub Actions по SSH** — нужен ключ SSH в секретах GitHub и открытый порт 22. Сервер, который сам забирает обновления, проще и безопаснее.
