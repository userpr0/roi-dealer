# ADR-0007: Воронка экспериментов — в собственной PostgreSQL

- **Status:** Accepted
- **Date:** 2026-10-19
- **Approved by:** владелец, D-020 (план до Уровня 2) и D-014 п.9 («инструмент аналитики выбирается ADR в PHASE 15»). Стек не меняется, платных сервисов нет — остановка не требуется.

## Context

- **Требования D-014 п.9:**
  - все эксперименты пишут одни и те же события воронки: показ → внимание → клик → активация → заявка → оплата → использование → результат → возврат;
  - у каждого события — `experiment_id`, `hypothesis_id`, канал, UTM-метки и время в UTC;
  - метрика успеха считается из событий детерминированно (§7.3);
  - инструмент — с уважением к приватности, без передачи персональных данных третьим лицам без необходимости.
- **На Уровне 2 своих страниц у системы нет** (сборка лендингов — PHASE 19). Тест запускает владелец:
  - лендинг на внешнем конструкторе;
  - объявление;
  - прямые сообщения;
  - интервью.

  Цифры приходят из кабинетов площадок и из рук владельца — сводными числами за период.

- **Лимиты D-007:**
  - инфраструктура — $20 в месяц;
  - новый платный сервис — только через ADR и одобрение (D-020).

## Decision

1. **Журнал `experiment_events` в той же PostgreSQL** (миграция `0012`). Одна схема для всех источников:
   - эксперимент и гипотеза — со связью через внешний ключ;
   - шаг воронки из фиксированного списка, количество (1–1 000 000), канал;
   - UTM-метки (необязательно), время события в UTC;
   - источник и кто записал.
   - Только добавление, как у остальных журналов.
2. **Источники:**
   - `owner_report` — сводные цифры владельца через `/funnel` (PHASE 15);
   - `tracker` — события собственных страниц через `apps/api` (PHASE 13 / 19), без cookies и без персональных данных.
3. **Итоги и метрика:**
   - итоги — `sum(quantity)` по шагу в SQL;
   - значение метрики и «достигнута ли» — функции домена (`metricValue`, `metricReached`);
   - AI в подсчёте не участвует.
4. **Никаких сторонних аналитических скриптов** на тестовых страницах, пока для этого нет отдельного ADR.

## Consequences

- **Плюсы:**
  - $0;
  - метрика каждого теста считается одинаково и проверяется тестами;
  - итоги воронки доступны `/experiments`, Company Brain и будущей экономике (PHASE 16) одним SQL.
- **Минусы:**
  - сбор событий со страниц (`tracker`) нужно написать: эндпоинт с ограничением частоты, без персональных данных;
  - пока своих страниц нет, точность зависит от цифр, которые вносит владелец. Их видно в подтверждении «было → станет».
- **Следующие фазы:**
  - PHASE 13 (`apps/api`) и 19 (страницы) пишут события `tracker` в ту же таблицу;
  - PHASE 16 строит экономику из `cost_entries` и этой воронки.

## Rollback

Перейти на внешний инструмент — новый ADR. События выгружаются из `experiment_events` (CSV или API инструмента). Метрики продолжают считаться из той же таблицы, если инструмент отдаёт события обратно. Таблица и данные остаются: журнал только добавляется.
