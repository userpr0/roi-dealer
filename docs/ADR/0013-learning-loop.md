# ADR-0013: Обучающийся цикл — прогноз и факт, портфель ставок, возврат отсечённого, своя аудитория, офферы

- **Status:** Proposed
- **Date:** 2026-11-04
- **Approved by:** —

## Context

ROI Dealer задуман как венчурная студия: много маленьких проверенных ставок, и система учится на каждой. Сейчас круг собран — боль, оценка, решение владельца, тест, деньги, ROI процессов (16b), — но после теста система ничего не узнаёт:

- веса `scoreOpportunity` заданы вручную и не меняются от исходов;
- бюджет одобряется на каждый тест отдельно, распределения между ставками нет;
- отклонённое и закрытое не отслеживается: если отсечённая тема потом «выстрелит», система этого не заметит;
- своей аудитории (подписчиков) нет: каждый тест начинается с нуля;
- партнёрские предложения не сравниваются: можно продешевить.

Владелец: «Что из этого реально сделать на текущей базе — давай добавим», «Своя аудитория… нужно добавить», «нужно еще отдел для поиска лучших предложений», «а если… то, что мы ранее отсекли, выстрелит?».

## Decision (предложение)

Пять частей. Все числа считает код (§2.13), AI только предлагает тексты; решения — за владельцем.

### 1. Прогноз → факт и калибровка

- **Журнал `forecasts`:** при оценке возможности и при запуске теста код записывает прогноз — вероятность успеха теста и ожидаемую конверсию, с версией правил оценки и значениями сигналов (ширина по площадкам, число независимых сигналов, денежные цитаты, тренд «Пульса», баллы судей).
- **Факт** записывается при завершении теста: метрика и вердикт гипотезы (они уже считаются кодом).
- **Калибровка:** точность прогнозов (Brier score) по версиям правил — в `/roi` и недельном разборе.
- **Новые веса** код считает по накопленным исходам (логистическая регрессия), когда завершённых тестов не меньше 20. Это **предложение новой версии правил**: владелец одобряет его карточкой; до одобрения действуют прежние веса. Так соблюдается правило «вес меняется только решением владельца после проверки на примерах».

### 2. Портфель ставок и правила остановки

- Владелец задаёт **месячный бюджет тестов и лимит на одну нишу и страну**.
- Распределитель (код, сэмплирование Томпсона по наблюдаемым конверсиям) **рекомендует**, какие одобренные гипотезы получают деньги в этом месяце. Запуск — как сейчас: одобренный `experiment_launch` на каждый тест.
- **Правила остановки** — статистические, кодом: тест останавливается рано, когда уже ясно, что он хуже порога или лучше него, а не только по календарю. Защита от ложной победы: минимальная выборка.

### 3. Лист наблюдения: возврат отсечённого

Ответ на вопрос «а если отсечённое выстрелит»:

- Каждая отклонённая или закрытая боль и возможность попадает в **лист наблюдения** с причиной и снимком сигналов на момент решения.
- Система продолжает следить за её темой: новые сигналы, «Пульс», новые площадки.
- Когда сила сигналов вырастает выше порога (например, вдвое и на новых площадках), владелец получает карточку **«Вернуть на рассмотрение?»** с тем, что изменилось. Решает владелец.
- Если возвращённое потом окупается, это записывается как **ложный отказ** и идёт в калибровку (часть 1): правила учатся не отсекать такое снова.

### 4. Своя аудитория

- На лендингах — **отдельная галочка** «присылать письма по теме» (не путать с заявкой). Двойное подтверждение по почте, отписка в каждом письме (GDPR, CAN-SPAM).
- Адреса — только в отдельном хранилище персональных данных, как почта лидов (`lead_contacts`): без событий, удаляются по-настоящему.
- Учитываются **свои каналы**: подписчики рассылки, Telegram-канала ниши, аккаунтов Gen_Content (через официальные API площадок). Отчёт «аудитория как актив»: рост, отток, доля, ставшая покупателями.
- Сервис отправки писем — платный и внешний: выбирается **отдельным ADR**, когда список дойдёт до первых сотен адресов. До этого только сбор с согласием и счёт.

### 5. Офферы: поиск лучших предложений

- Источники — **только официальные API партнёрских сетей** для издателей (кандидаты: Impact, CJ, Awin, Rakuten, ShareASale; Amazon Associates — позже, у него требование по продажам). Каждая сеть сначала проходит разведчика (условия).
- Сравнение кодом по каждой боли и стране: комиссия, EPC, срок cookie, порог выплаты, **разрешены ли трафик из соцсетей и AI-контент**, совпадение с темой.
- Лучшие офферы — рекомендация в карточке возможности; ссылку в контент добавляет только одобренный владельцем оффер, всегда с пометкой рекламы или партнёрской ссылки.

## Что не меняется

Стек (TypeScript, PostgreSQL, Railway/Hetzner), история событий, правила денег D-006/D-007, решения только владельца, проверка честности контента.

## Alternatives

| Вариант                                             | Почему не выбран                                                          |
| --------------------------------------------------- | ------------------------------------------------------------------------- |
| Учить веса AI-моделью                               | Нарушает §2.13: числа — только код; модель непрозрачна для владельца      |
| Сразу менять веса автоматически                     | Владелец должен видеть и одобрять смену правил оценки                     |
| Отдельная БД аналитики (ClickHouse, BigQuery)       | Объём — сотни тестов, не миллионы; PostgreSQL хватает. Вернёмся при росте |
| Своя рассылка без внешнего сервиса                  | Доставляемость писем требует репутации отправителя; самому не обеспечить  |
| Офферы по выдаче поиска или скрейпингу сайтов сетей | §2.21: только официальные API                                             |

## Consequences

- Новые таблицы: `forecasts`, `watchlist`, `audience_contacts` (персональные данные, как `lead_contacts`), `offers`. Миграции — по фазам.
- Калибровка начинает работать после ~20 завершённых тестов; до этого журнал копит данные.
- «Геном креатива» (параметры каждого ролика и их результат) — часть фазы 24 (связь с Gen_Content), он ложится на тот же журнал прогнозов.

## Rollback

До миграций — отклонить. После — выключить фазу; журналы остаются, на текущий цикл они не влияют (веса меняются только одобренной версией).
