# ADR-0003: Ранний Telegram-модуль — бот-пульт владельца

- **Status:** Accepted
- **Date:** 2026-09-24
- **Approved by:** владелец, 2026-09-24. Ответы в сессии: объём — «Бот-пульт для вас», хостинг — «Облачный сервер 24/7»

## Context

По карте реализации интеграция с Telegram относится к PHASE 13 (Owner Command Center). Владелец попросил подключить Telegram API сейчас, до PHASE 01. Placeholder miniapp уже опубликован и открывается из бота (ADR-0002).

Бизнес-данных в системе ещё нет, поэтому первый шаг должен дать защищённый канал управления без функций «на всякий случай» (§2.14, §2.15).

## Decision

1. **Объём (фаза 13a):** бот отвечает только владельцу; команды только на чтение: `/start`, `/status` (здоровье, версия, окружение, аптайм), `/help`; уведомления владельцу о запуске и остановке бота.
2. **Вне объёма:** данные в Mini App и проверка `initData`, команды, меняющие состояние, webhook, группы и другие пользователи.
3. **Новый пакет `@roi-dealer/telegram`:** собственный тонкий клиент Bot API (`fetch` + Zod) без стороннего bot-фреймворка; long polling; маршрутизатор команд с доступом только для владельца; notifier.
4. **Приём обновлений — long polling (`getUpdates`):** не нужен публичный endpoint. Поддерживается только один экземпляр на токен (иначе Telegram возвращает 409).
5. **Доступ:** обрабатываются только личные сообщения от `TELEGRAM_OWNER_USER_ID`; остальные отбрасываются без ответа; в логах только `user_id`, текст сообщений не логируется.
6. **Команды типизированы** (`BotCommandDefinition`). Команды, меняющие состояние системы, в будущем обязаны запрашивать явное подтверждение владельца (Input Router, playbook §3 #16).
7. **Секреты:** `TELEGRAM_BOT_TOKEN` берётся только из окружения (секретные переменные хостинга или локальный `.env`); значение не попадает в логи и ошибки; Bot API вызывается только по HTTPS (HTTP разрешён только для localhost в тестах).
8. **Развёртывание:** Docker-образ `apps/bot/Dockerfile` для любого container-хостинга; рекомендуемый вариант — Railway (деплой из GitHub, переменные в веб-интерфейсе). Аккаунт хостинга создаёт владелец. Инструкция — [`docs/deploy/telegram-bot.md`](../deploy/telegram-bot.md).
9. **Завершение:** бюджет shutdown 8 s, таймаут запросов к Telegram 5 s — укладывается в стандартное окно SIGTERM → SIGKILL (10 s) container-платформ.
10. **CI** собирает Docker-образ бота на каждый push / PR.

## Alternatives

| Вариант                                   | Почему не выбран                                                                                              |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| grammY / Telegraf                         | Для трёх команд лишняя зависимость; переход возможен позже за API пакета `@roi-dealer/telegram`               |
| Webhook                                   | Нужен публичный HTTPS endpoint и проверка `secret_token`; оправдан при росте нагрузки или serverless-хостинге |
| Serverless (Cloudflare Workers + webhook) | Требует иной модели процесса; можно рассмотреть позже                                                         |
| Запуск на ПК владельца                    | Владелец выбрал облачный сервер 24/7                                                                          |
| Сразу Mini App с данными                  | Нет данных для показа; нужен публичный API — отдельное решение                                                |

## Consequences

- **+** Защищённый канал «система → владелец» и «владелец → система» с первого дня; основа для approvals и alerts.
- **+** Нулевые новые runtime-зависимости; код клиента покрыт тестами на поддельном Bot API.
- **−** Бот должен работать в **одном** экземпляре; локальный запуск с тем же токеном конфликтует с облачным (используйте отдельного тестового бота).
- **−** Появляется платный внешний ресурс (хостинг, ориентировочно ~$5/мес — проверить актуальную цену у провайдера).
- **−** Отклонение от порядка Phase: PHASE 01–12 по-прежнему требуются для реальных данных в пульте.

## Rollback

Остановить сервис у хостинг-провайдера; в @BotFather выполнить `/revoke` для токена; удалить `apps/bot/Dockerfile`, пакет `@roi-dealer/telegram` и вернуть skeleton `apps/bot`. Данных в БД нет — откат без миграций.
