# ADR-0017: Потребности по странам и вертикалям — четыре вида, ищейки по темам, риск-фильтр

- **Status:** Proposed
- **Date:** 2026-11-26
- **Approved by:** —

## Context

**Слова владельца:**

- 2026-11-19: «Мы будем не только боль … но и решение, удобство и впечатления».
- 2026-11-26: развивать это «в каждой стране индивидуально (например берем гео USA)»; «под каждую вертикаль отдельно делать своих "ищеек" для трендов, спроса, популярности, необходимости и всего что нам может помочь в заработке».
- 2026-11-26: «Видео YouTube и посты в инсте, видео в тик ток, Telegram посты берем для анализа и оценки рисков».

**Что есть сейчас:**

- Конвейер находит только боли (фаза 06) на рынках D-008. Ни вида потребности, ни вертикали у боли нет.
- Темы `/seek` общие, не привязаны к вертикали.
- Правила честности проверяются на уровне текста страницы и пакета. Риска вертикали целиком система не видит.
- Каталог источников: статистика чужих видео YouTube и каналы Telegram отклонены условиями площадок (разведчик 23.11).

Новые поля у болей и новые журналы — смена модели данных, поэтому нужен ADR.

## Decision

1. **Четыре вида потребности.** У каждой найденной потребности есть вид:
   - `pain` — боль: что мешает, раздражает, стоит денег или времени;
   - `solution` — ищут готовое решение: «чем заменить…», «лучший сервис для…»;
   - `convenience` — удобство: то, что уже делают, хотят быстрее, проще или дешевле;
   - `experience` — впечатления: события, подарки, путешествия, эмоции.

   Вид ставит AI-задача анализа доказательств (новая версия задачи агента болей) вместе с цитатой. Код, как и сейчас, держит потребность, только если цитата есть в тексте доказательства. Эталоны — по каждому виду.

2. **Страна и вертикаль.**
   - **Страна** — рынок D-008, первым идёт США.
   - **Вертикаль** — из реестра `VERTICALS` в коде. Каждая вертикаль совпадает с вертикалью библиотеки (фаза 35).
   - **Запрещённых вертикалей в реестре нет** — по разделу 6 инструкции: адалт, нутра-офферы с обещаниями здоровья.
3. **Ищейки — это наборы тем, а не отдельный код на каждую вертикаль.**
   - **Свой набор.** У вертикали — набор тем: простые слова для каждого рынка, журнал `vertical_topics`. Владелец добавляет тему командой `/seek <вертикаль> <слова>` с подтверждением.
   - **Как ищет.** Агент исследований ищет по набору через `collectEvidence` в разрешённых источниках, каждую тему один раз, с долей дневного бюджета AI на вертикаль.
4. **Оценка кодом — своя у каждого вида (§2.13):**
   - **боль** — сила и частота, как сейчас;
   - **решение** — число сигналов «ищу / чем заменить» и цитаты с готовностью платить;
   - **удобство** — упоминания потерянного времени и денег;
   - **впечатления** — сезоны и события «Пульса».

   Веса видов в оценке возможности задаёт владелец — после проверки на примерах, как вес «Пульса».

5. **Риск-фильтр вертикали — код, не AI.** У вертикали — уровень и правила:
   - **ограничена:** здоровье — без медицинских обещаний; деньги — без обещаний дохода и инвестиционных советов; красота — AI-персонаж не пишет отзывов «я попробовала»; дейтинг — персонаж не флиртует;
   - **обычная** — общие правила раздела 6.

   Правила вертикали проверяются в уже существующих проверках каждого черновика: ролика, страницы, продукта, оффера. Уровень риска виден на карточке радара.

6. **Источники для анализа — только законные пути:**

   | Источник  | Можно                                                                                                                                       | Нельзя                                                                      |
   | --------- | ------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
   | YouTube   | Ссылка владельца на отдельный ролик → разбор Gemini по ссылке; хранится карточка приёма, а не ролик. Свои каналы — через API                | Массовый сбор статистики чужих видео через API — условия YouTube            |
   | Instagram | Свои аккаунты — через официальный API. Реклама конкурентов — библиотека рекламы Meta вручную. Её API и поиск по хэштегам проверит разведчик | Скрейпинг и скачивание чужих постов                                         |
   | TikTok    | Свои аккаунты — через API. Тренды и топ-реклама — TikTok Creative Center вручную. Commercial Content API проверит разведчик                 | Скачивание чужих роликов                                                    |
   | Telegram  | Владелец читает сам и пишет заметку своими словами                                                                                          | Бот системы не собирает чужие посты и не разбирает их AI — условия Telegram |

   Заметки и ссылки владельца входят в систему как его наблюдения. Копий чужих материалов система не хранит — только параметры приёма (§2.20).

7. **Выход — радар `/radar <страна> <вертикаль>`:**
   - главные потребности каждого вида — с числами, источниками и трендом;
   - уровень риска вертикали.

   Радар питает возможности (действующий конвейер), очередь персонажей завода, продукты и предложения услуг для бизнеса.

8. **Фазы.** Спецификация фазы 06b «Потребности по странам и вертикалям» — после принятия ADR. Радар трендов завода — Gen_Content 03 по D-023, с этими же правилами источников.

## Alternatives

| Вариант                                        | Плюсы            | Минусы                                                 | Почему не выбран                           |
| ---------------------------------------------- | ---------------- | ------------------------------------------------------ | ------------------------------------------ |
| Отдельный агент-код на каждую вертикаль        | Полная настройка | Дублирование кода, каждая новая вертикаль — разработка | Набор тем даёт то же без нового кода       |
| Сбор статистики площадок неофициальными путями | Много данных     | Нарушение условий (§2.21), блокировки аккаунтов        | Только официальные API и ручные наблюдения |
| Ранжирование вертикалей AI                     | Быстро           | Числа от AI (§2.13), не проверяемо                     | Считает код, решает владелец               |
| Оставить только боли                           | Нет работы       | Не видно спроса на решения, удобство и впечатления     | Владелец просил четыре вида                |

## Consequences

- **Плюсы:**
  - видно, что нужно людям в каждой стране и вертикали;
  - персонаж, продукт и услуга выбираются по цифрам, а не по ощущению.
- **Минусы:**
  - миграция: вид и вертикаль у потребностей, журнал тем;
  - новая версия AI-задачи с эталонами;
  - дневной бюджет AI делится между вертикалями;
  - по площадкам без разрешённого API — ручная работа владельца: ссылки и заметки.

## Rollback

- **Поля:** вид по умолчанию — `pain`, вертикаль — пусто. Это прежнее поведение.
- **Темы и радар:** журнал тем и радар отключаются без влияния на остальной конвейер.
