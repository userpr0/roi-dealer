# ADR-0005: Драйвер PostgreSQL и миграции

- **Status:** Accepted
- **Date:** 2026-09-25
- **Approved by:** владелец, 2026-09-25 — приёмка PHASE 02 ответом «продолжай дальше» на запрос одобрения PHASE 03 (D-016)

## Context

PHASE 02 (PostgreSQL Foundation) требует драйвер базы данных, инструмент миграций и репозитории для 13 сущностей PHASE 01. [`TECH_STACK.md`](../TECH_STACK.md) предписывает выбрать инструмент через ADR. Канонический стек не меняется: PostgreSQL остаётся источником истины (§2.1), TypeScript — языком backend.

Ограничения:

- **Политика зависимостей:** новая зависимость — только если без неё нельзя; install-скрипты зависимостей запрещены (`onlyBuiltDependencies: []`).
- **Доменная модель — источник правды о сущностях.** Схемы Zod в `@roi-dealer/domain` уже описывают поля и правила; второй источник правды (ORM-схема) создал бы расхождения.
- **Constraints в БД** (playbook: «migrations, repositories, constraints, UUID, UTC»): миграции должны свободно использовать весь SQL PostgreSQL — CHECK, domains, триггеры, составные внешние ключи.
- **Строгий TypeScript** (`exactOptionalPropertyTypes`, `verbatimModuleSyntax`, NodeNext).
- Бюджет инфраструктуры $20/мес (D-007): никаких платных сервисов для миграций.

## Decision

1. **Драйвер — [`postgres`](https://github.com/porsager/postgres) (postgres.js) `^3.4.9`.**
   - Ноль runtime-зависимостей, без install-скриптов, типы в пакете.
   - Параметры запросов передаются только через tagged templates: подставить значение в текст SQL без экранирования нельзя по построению.
   - Встроенный пул соединений, транзакции (`begin`) и savepoints; сессия открывается с `TimeZone=UTC`.
   - Ошибки `PostgresError` несут SQLSTATE и имя constraint — репозитории переводят их в свои ошибки без значений полей.
2. **Миграции — SQL-файлы и собственный раннер** в `@roi-dealer/database` (около 150 строк).
   - Файлы `database/migrations/NNNN_name.sql`, только вперёд; применённый файл не редактируется.
   - Журнал `schema_migrations` хранит id, SHA-256 содержимого и время применения. Изменённый после применения файл или миграция из БД, которой нет в коде, останавливают раннер с ошибкой.
   - Каждая миграция выполняется в своей транзакции под `pg_advisory_xact_lock`, поэтому два процесса, запущенные одновременно, не применят одну миграцию дважды.
   - Запуск: `pnpm db:migrate` (локально и в CI); в облаке — тот же раннер отдельным шагом деплоя, когда появится первый облачный потребитель БД.
3. **Репозитории — явный SQL и ручное отображение строк**, без ORM и query builder. Каждая прочитанная строка проверяется схемой Zod из `@roi-dealer/domain` (§2.13 Retrieval Before Reasoning): повреждённые данные не доходят до бизнес-логики молча.

## Alternatives

| Вариант                                | Плюсы                                  | Минусы                                                                                                             | Почему не выбран                                                               |
| -------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| `pg` (node-postgres) + `@types/pg`     | Самый распространённый драйвер         | 6 транзитивных пакетов и отдельные типы; параметры `$1` — строки SQL собираются вручную                            | postgres.js даёт то же с нулём зависимостей и безопасными шаблонами            |
| Kysely (query builder) поверх драйвера | Типизированные запросы                 | Ещё одна зависимость и второе описание таблиц рядом с доменом                                                      | Для репозиториев из insert / get / update достаточно SQL; можно добавить позже |
| Drizzle ORM + drizzle-kit              | Схема в TypeScript, генерация миграций | Второй источник правды о сущностях; drizzle-kit тянет esbuild и десятки пакетов; сгенерированный SQL хуже ревьюить | Противоречит «домен — источник правды» и политике зависимостей                 |
| Prisma                                 | Зрелый ORM                             | Бинарный движок, install-скрипты, собственный язык схем                                                            | Запрещённые install-скрипты, vendor lock-in                                    |
| node-pg-migrate                        | Готовый раннер миграций                | Требует `pg` и CLI-зависимости; наш раннер проще проверить тестами                                                 | Раннер на ~150 строк с проверкой checksum и блокировкой прозрачнее             |

## Consequences

- **Безопасность:** SQL-инъекции через значения невозможны (tagged templates); ошибки БД логируются кодом SQLSTATE и именем constraint, без значений строк (`detail` не логируется); `DATABASE_URL` редактируется логгером.
- **Стоимость:** $0 — только open-source пакет.
- **Сложность:** SQL для 13 таблиц и отображение строк пишутся вручную; это больше кода, чем с ORM, но каждое правило видно в миграции и покрыто тестом.
- **Vendor lock-in:** минимальный. Драйвер скрыт за API `@roi-dealer/database`; SQL — стандартный PostgreSQL 18.
- **Следующие фазы:** PHASE 03 (Event History) добавляет таблицы новыми миграциями и пишет события в той же транзакции через `database.transaction(...)`.

## Rollback

Замена драйвера затрагивает только `packages/database`: API пакета (`createDatabase`, репозитории, `runMigrations`) остаётся прежним. SQL-миграции и данные не зависят от драйвера. Таблица `schema_migrations` принадлежит нашему раннеру; при переходе на другой инструмент её содержимое переносится одним скриптом.
