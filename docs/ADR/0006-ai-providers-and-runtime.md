# ADR-0006: AI-провайдеры и AI Runtime

- **Status:** Accepted
- **Date:** 2026-10-18
- **Approved by:** владелец:
  - D-020 — план до Уровня 2; ADR на SDK AI-провайдеров назван в плане и укладывается в лимит AI $50/мес (D-007);
  - D-021 — третий провайдер Gemini, «каждый делает то, что умеет лучше», бюджет токенов на весь день.

## Context

PHASE 09 подключает AI для задач, где правила не справляются. Первая такая задача — найти имена людей в тексте Evidence.

Владелец хочет использовать Claude, GPT и Gemini, и чтобы каждый делал то, что у него получается лучше всего. Ещё одно требование: AI-бюджета должно хватать на все процессы в течение всего дня.

Ограничения:

- **§2.4:** провайдеры заменяемы, домен к ним не привязан (TECH_STACK).
- **Политика зависимостей:** новая зависимость — только если без неё нельзя; install-скрипты не выполняются.
- **Лимит AI — $50 в месяц** (D-007): жёсткий в коде и у провайдеров.
- **Evals с первой задачи** (D-014 п.7).
- **Из среды разработки** API провайдеров недоступны: проверка — на фейковых серверах; настоящие вызовы — в worker с ключами владельца.

## Decision

### 1. Официальные SDK

| Провайдер | SDK                 | Runtime-зависимости                                                                                                              |
| --------- | ------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Anthropic | `@anthropic-ai/sdk` | `json-schema-to-ts`, `standardwebhooks`, `@opentelemetry/api`                                                                    |
| OpenAI    | `openai`            | нет                                                                                                                              |
| Google    | `@google/genai`     | `google-auth-library`, `p-retry`, `protobufjs`, `ws`. Postinstall `protobufjs` — только предупреждение о версиях, не выполняется |

- SDK используются только внутри адаптеров `@roi-dealer/ai-runtime`. Остальной код вызывает `runTask`.
- Автоповторы SDK выключены: повтор и переход на другую модель решает маршрутизатор.

### 2. Структурированный ответ

- Схема Zod задачи превращается в JSON Schema и передаётся провайдеру:
  - Anthropic — `output_config.format`;
  - OpenAI — `text.format` (`zodTextFormat`);
  - Gemini — `responseJsonSchema`.
- Ответ разбирает адаптер, а не SDK. Поэтому токены невалидного ответа тоже учитываются в расходах.
- Невалидный, обрезанный ответ или отказ модели — это сбой (`invalid_output`, `refusal`), а не данные.

### 3. Модели и уровни

Реестр моделей — в коде. Цены указаны в долларах за 1M токенов.

| Уровень                                      | Модели                                                                                                                                          |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `bulk` — массовая обработка                  | `claude-haiku-5-5` ($0.10 / $0.50), `gemini-3.1-flash-lite` ($0.25 / $1.50, размышления оплачиваются как вывод), `gpt-5.4-mini` ($0.75 / $4.50) |
| `strong` — оценки и суждения (с PHASE 06/11) | `claude-opus-5-5` ($4 / $20); сильные модели OpenAI и Google добавятся с первой `strong`-задачей                                                |

- **Источники цен:**
  - Anthropic — справочник Claude API;
  - Google — страница цен Gemini API (платный уровень);
  - OpenAI — сторонние сводки 2026 года.
- При запуске worker проверяет каждую модель по списку моделей провайдера. Модель, которой нет в списке, не используется — это видно в логе.

### 4. Кто что делает (D-021)

Порядок моделей для задачи определяют её evals, а не порядок в реестре:

- **`bulk`:** первой идёт самая дешёвая модель из прошедших эталон — по стоимости прогона одного и того же набора;
- **`strong`:** первой идёт самая точная модель — по среднему метрик эталона;
- **запасная:** следующая модель **другого провайдера** — сбой одного провайдера стоит одну попытку.

Сильные стороны провайдеров под наши цели. Это стартовое распределение — evals его подтверждают или меняют.

| Провайдер | Лучше всего для ROI Dealer                                                                                                                                     | Где                      |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------ |
| Claude    | Внимательное чтение и суждения: судьи, карточки решений, гипотезы; Haiku — дешёвая массовая обработка                                                          | PHASE 09, 06, 11, 12, 14 |
| Gemini    | Объём и длинный контекст по низкой цене; видео и аудио (паттерны креативов, §2.20); поиск Google как источник контекста рынка — после проверки условий (§2.21) | PHASE 06, 10, 19a        |
| GPT       | Второе независимое мнение у судей (другая семья моделей — меньше общих ошибок); запасная модель структурированного извлечения                                  | PHASE 09, 11             |

### 5. Деньги (D-007, D-021)

- **Журнал:** каждый вызов пишется в `ai_calls` — стоимость в микродолларах.
- **Перед каждой попыткой** проверяются:
  1. месяц: не больше $50;
  2. дневная квота: остаток месяца, делённый на оставшиеся дни, но не больше $20. Тихий день оставляет больше следующим;
  3. доля дня этого процесса: у каждой задачи своя (`dailyShare`), у evals — 20 %. Сумма долей не больше 1 — это проверяет тест.
- **Резерв:** каждая проверка резервирует худшую стоимость вызова (`maxCostMicroUsd`). Тест сверяет её с худшим случаем по ценам реестра.
- **Учёт расходов:** раз в сутки сумма за день записывается `CostEntry` категории `ai`. Дневной предел не даёт превысить порог одобрения $20 (D-006).

### 6. Evals

- Задача не выполняется на модели без проходного отчёта на эталонном наборе (от 20 примеров) для своей версии промпта.
- Отчёт — `KnowledgeAsset` с тегами и метриками. Из него маршрутизатор берёт стоимость и точность.
- Новая версия промпта или новая модель требует нового прогона. Worker делает его сам в пределах доли evals.

## Расчёт токенов на день

- **Квота дня:** $50 / 30 дней ≈ **$1.67** (в 31-дневном месяце $1.61).
- **Вычистка имён** (PHASE 09, сейчас):
  - один вызов ≈ 370 токенов на входе (инструкция ≈ 110 + цитата до 1 000 символов) и ≈ 120 на выходе;
  - стоимость вызова: Haiku ≈ $0.0001, Gemini Flash-Lite ≈ $0.0003, GPT-5.4 mini ≈ $0.0008;
  - Hacker News даёт до 30 новых постов в час — до 720 в день, обычно 30–60;
  - худший день на Haiku ≈ $0.07 при доле $0.16.

| Процесс                      | Фаза | Уровень | Вызовов в день                 | ≈ $ в день             | Доля дня    |
| ---------------------------- | ---- | ------- | ------------------------------ | ---------------------- | ----------- |
| Вычистка имён в Evidence     | 09   | bulk    | 30–60, до 720                  | < $0.01, до $0.07      | 10 %        |
| Evals новых версий и моделей | 09   | все     | 24 на модель, только при смене | ≈ $0.03 за прогон      | 20 %        |
| Сигналы и боли из Evidence   | 06   | bulk    | столько же, сколько Evidence   | до $0.15               | 15 % + 5 %  |
| Формулировка возможностей    | 07   | bulk    | несколько болей в день         | ≈ $0.002 за боль       | 10 %        |
| Агенты: исследование, рынок  | 10   | оба     | ≈ 20                           | ≈ $0.40                | 20 % (план) |
| Судьи по возможностям        | 11   | strong  | 6 на возможность               | ≈ $0.19 на возможность | 20 % (план) |

**Вывод:**

- Массовая обработка дешёвая: меньше $0.25 в день даже в худший день.
- Дорогие процессы — агенты и судьи.
- При $50 в месяц система полностью оценивает примерно 2 возможности в день. Если их будет больше, лимит поднимает владелец.
- Доли не дают одному процессу съесть день: каждый получает свою часть. Если доля закончилась, процесс ждёт следующего дня (сбор Evidence при этом продолжает чистить данные правилами).

## Alternatives

| Вариант                                | Почему не выбран                                                                                                               |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Прямые HTTP-запросы без SDK            | Больше своего кода (ошибки, разбор ответа); руководство Claude API требует официальный SDK там, где он есть                    |
| Один или два провайдера                | Владелец хочет три (D-021); запасной провайдер закрывает сбои и отказы                                                         |
| Агрегатор (OpenRouter и т. п.)         | Лишний посредник с данными и наценкой; противоречит §2.21 о прямом официальном доступе                                         |
| LangChain / Vercel AI SDK              | Десятки зависимостей и своя абстракция поверх нашей `runTask`                                                                  |
| Ручное распределение «задача → модель» | Мнение вместо измерения: evals показывают реальную точность и стоимость на наших данных и сами меняют порядок при новой модели |
| Ровный дневной лимит без долей         | Один процесс (например, evals новой модели) мог бы съесть весь день и оставить остальные без AI                                |

## Consequences

- Три новые зависимости в `@roi-dealer/ai-runtime` и в образе worker.
- **Ключи** `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY` хранятся только в Variables сервиса worker в Railway — никогда в чате и в репозитории. Логгер их редактирует.
- **Ключ Gemini — только с включённой оплатой.** На бесплатном уровне Google может использовать запросы для улучшения продуктов.
- **Данные у провайдеров:** провайдерам уходят тексты Evidence для обработки. Это публичные посты без контактов (PHASE 05). OpenAI-запросы отправляются с `store: false`.

## Rollback

- Удалить ключ провайдера в Railway — его модели перестают использоваться, работают остальные.
- Удалить все ключи — AI выключен, сбор Evidence продолжает работать с очисткой правилами.
- Откат кода — удалить адаптер и его зависимость.
