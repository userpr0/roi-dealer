# ADR-0018: Библиотека креативов в Telegram

- **Status:** Proposed
- **Date:** 2026-11-23
- **Approved by:** —

## Context

**Требование владельца** (2026-11-23, D-043): «Библиотека креативов в тг по каждому видео должна быть пометка гео/вертикаль/просмотры/дата загрузки/триггеры и все что поможет нам». Поля карточки — в [`phases/37_creative_library.plan.md`](../phases/37_creative_library.plan.md).

**Что уже есть:**

- **Фаза 36** связывает каждую заявку, звонок, показ и сделку с материалом через метку `m=` (D-042). Но самих материалов — роликов с их приёмами и цифрами — в системе нет.
- **Фаза 35** раскладывает объекты по дереву «вертикаль → проект → тема». Ролик там не объект.
- **Gen_Content** хранит свои ролики (`videos`: вертикаль, формат, язык, персонаж). Но ролики бывают и из других источников: монтаж в сессии Claude, монтаж владельца, материалы клиента.
- **Цифры роликов** площадки показывают владельцу аккаунта. Официальные API своих аккаунтов есть (Instagram, YouTube, TikTok), но каждое нужно проверить по условиям и настроить.

Новые таблицы и новый адресат бота — закрытый канал владельца, — поэтому нужен ADR.

## Decision

1. **Где живёт.** В ROI Dealer — рядом с заявками, сделками и выручкой. Gen_Content позже передаёт карточки своих роликов сам, через обмен фазы 24 (ADR-0011). До этого ролик регистрирует владелец или Claude.
2. **Сущность `Creative`** — с версиями и событиями.
   - Код — он же метка `m=`. Уникален, только латиница, цифры и дефис.
   - Поля паспорта, анатомии, прав и честности — по таблице из файла требований.
   - Место в библиотеке — тема фазы 35; ссылка на объект фазы 36 или на тест.
   - Статусы: `draft` → `published` → `archived`.
3. **Размещения `creative_placements`.** Площадка, аккаунт, ссылка на публикацию, гео (страна, область, город), дата и время загрузки. У одного ролика может быть несколько размещений.
4. **Цифры `creative_stats`** — журнал только для добавления.
   - Одна запись: размещение × срез (24 ч, 7 дн, 30 дн) × показатели из файла требований.
   - У записи есть источник (вручную или API) и автор. Действует последняя запись среза.
   - Только числа своих аккаунтов: ни имён зрителей, ни текстов комментариев.
5. **Деньги не дублируются.** Заявки, звонки, показы и сделки берутся из воронки объекта по `m=`, выручка — из леджеров. Расходы на ролик и его ROI — позже, с обменом фазы 24 и платными роликами (Feature Kill Gate).
6. **Вывод считает код (§2.13).**
   - Ролик сравнивается с медианой своего формата на той же площадке в том же срезе: «лучше», «как обычно» или «хуже».
   - Предлагаемый порог — ±30 %. Порог утверждает владелец вместе с этим ADR.
   - Пока роликов формата меньше 5, вывода нет: «мало данных».
   - AI не ставит выводов и не считает цифр.
7. **Канал Telegram.**
   - Закрытый канал владельца «Креативы». Бот — администратор с правом публиковать и редактировать; `CREATIVES_CHANNEL_ID` задаётся в переменных бота.
   - **Пост.** Опубликованный ролик — один пост: видео по его `file_id` в Telegram и подпись до 1024 знаков (код, название, хэштеги, дата загрузки, площадки, цифры срезов, заявки и сделки, вывод).
   - **Обновление.** После каждого среза бот правит подпись того же поста.
   - **Хэштеги** — из постоянных словарей в коде: гео, область, вертикаль, проект, формат, хук, мотив, голос, площадка, итог.
   - **Итоги недели.** По понедельникам — пост «итоги недели»: лучшие и худшие ролики по главной цифре формата.
   - **Только запись.** Бот в канал пишет, но канал не читает. Команды бот по-прежнему принимает только в личном чате владельца.
   - **Без персональных данных.** В канале нет телефонов, имён клиентов и текстов заявок. Источник правды — база: канал можно пересобрать из неё.
   - **Только через `@roi-dealer/telegram`.** Все вызовы Bot API идут через этот пакет; со стоп-краном публикация в канал останавливается.
8. **Ввод — в личном чате владельца.**
   - `/creative`: владелец присылает боту видео и отвечает на короткую анкету кнопками — гео, проект, формат, хук, мотив, площадки. Затем подтверждение и `database.command`.
   - `/stat <код>`: цифры среза с подтверждением. Сначала вручную — 5–10 минут в неделю.
   - Официальные API своих аккаунтов подключаются позже: сначала разведчик проверяет условия, затем доступ интеграции владелец одобряет в `/decisions`.
   - `/creatives` с хэштегами: список роликов с цифрами и выводом из базы.
   - Разметка анатомии AI по самому ролику — позже, отдельной AI-задачей с эталонами. Сначала — кнопки.
9. **Права.** Каждая команда и кнопка объявляет право и пишется в журнал доступа, как остальные команды пульта. Агенты карточки не меняют.
10. **Фаза 37.** Спецификация — после принятия ADR. Место в плане на 90 дней — после основы фазы 36.

## Alternatives

| Вариант                             | Плюсы                                  | Минусы                                                                                  | Почему не выбран                                         |
| ----------------------------------- | -------------------------------------- | --------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| Только канал, вручную, без базы     | Можно сегодня, без кода                | Нет расчёта, сравнения и связи с заявками; поиск только по тегам                        | Берём как старт: до кода владелец ведёт канал по шаблону |
| Библиотека в Gen_Content            | Анатомия роликов завода известна сразу | Ролики из других источников всё равно вручную; заявки и деньги — в ROI Dealer; два бота | Завод передаёт карточки через обмен (фаза 24)            |
| Google Таблица                      | Привычно                               | Новая интеграция и ключи; данные расходятся с базой                                     | Канал и база проще и без нового сервиса                  |
| Платные сервисы библиотек креативов | Готовый интерфейс                      | Платно, сделаны под рекламные кабинеты, данные у третьей стороны                        | При нашем объёме не нужны                                |

## Consequences

- **Плюсы:**
  - видно, какой ролик приносит заявки и деньги;
  - работающий приём повторяется, неработающий бросается раньше.
- **Минусы:**
  - цифры вводятся вручную раз в неделю, пока не подключены API;
  - у бота новый адресат — канал владельца.
- **Безопасность:**
  - в канале нет персональных данных;
  - бот канал не читает;
  - `file_id` — не секрет.
- **Стоимость:** $0. Видео хранит Telegram, в базе — несколько КБ на ролик.

## Rollback

- **Публикация в канал:** убрать `CREATIVES_CHANNEL_ID`. Бот перестаёт писать в канал; посты остаются у владельца.
- **Данные:** таблицы остаются для истории и на остальную систему не влияют.
