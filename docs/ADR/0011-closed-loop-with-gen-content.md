# ADR-0011: Замкнутый цикл ROI Dealer ↔ Gen_Content

- **Status:** Proposed
- **Date:** 2026-11-03
- **Approved by:** —

## Context

Владелец хочет одну машину, которая:

- находит боли в текущий период: сезон, событие, праздник, тренды;
- использует паттерны старых хитов (5–10 лет назад) и новых, которые набирают миллионы просмотров;
- комбинирует старое с новым;
- понимает, где потратить деньги, а где убрать затратный процесс.

Источники: документы владельца — MRAI, «Создание контент-завода по-китайски», папки Google Drive ROI DEALER, TMA_ROI DEALER и TRAFIC.

Что уже есть:

- **ROI Dealer** — «где деньги».
  - Боли из разрешённых источников (каталог — 49 записей, D-026).
  - Возможности, судьи, решения владельца, честные тесты с лендингами.
  - Экономика: леджеры, лимиты D-007, вердикт гипотезы кодом.
- **Gen_Content** (`userpr0/Gen_Content`) — «завод», работает от темы до пакета для публикации:
  - сценарий, озвучка Gemini, кадры, музыка;
  - монтаж ffmpeg, субтитры, громкость −14 LUFS, QA;
  - карточка в Telegram.

  Своя конституция:
  - паттерн, а не копия;
  - только разрешённый доступ;
  - честность AI-персонажей;
  - compliance-гейт в коде.

Проекты живут отдельно и не обмениваются данными. Поэтому:

- завод не знает, какие боли и сезоны сейчас приносят деньги;
- ROI Dealer не знает, сколько стоил и что принёс каждый ролик.

## Decision (предложение)

1. **Роли не смешиваем.**
   - ROI Dealer решает, что делать и сколько тратить.
   - Gen_Content производит и публикует.
   - Общих баз нет: только явный обмен через API с подписью, как вебхук Lemon Squeezy (ADR-0009).
2. **ROI Dealer → Gen_Content: «заказ».**
   - Состав: боль, рынок, цитаты-доказательства, окно «Пульса», бюджет.
   - Только по одобренной владельцем возможности или гипотезе.
3. **Gen_Content → ROI Dealer: «итог ролика».**
   - Стоимость производства: AI-вызовы и рендер.
   - Публикации и метки `start=video_<id>` / UTM.
   - Результат воронки: переходы, лиды, деньги.
   - Деньги учитываются только в леджерах ROI Dealer (`CostEntry`, `RevenueEntry`).
4. **«Пульс» — календарь на 2–6 недель по рынкам D-008: сезоны, праздники, события, рост интереса.**
   - Только из разрешённых источников каталога: просмотры Википедии, GDELT, Federal Register.
   - Google Trends — после одобрения заявки.
   - Новые источники — через разведчика.
   - Числа считает код, AI их не придумывает (§2.13).
5. **«Паттерны хитов».**
   - Структура хранится как параметры, не копия (§2.20): хук 0–3 с, ход «проблема → поворот → кульминация → призыв», длина, темп, эмоция.
   - Источники:
     - ссылки, которые присылает владелец (`ReferenceAsset` и `ReferenceRights` из плана 19b, права проверяются);
     - официальные API там, где разрешено;
     - главное — аналитика своих роликов.
   - «Старое + новое» — сочетание проверенной структуры с болью или трендом из «Пульса».
6. **«ROI процесса».** Раз в месяц по каждому процессу — сбор, сценарии, озвучка, рендер, реклама:
   - расход из леджеров;
   - результат: лиды и деньги;
   - вердикт кодом: оставить, масштабировать или убрать.

   Это Feature Kill Gate (§2.15), применённый к самой системе. Решает владелец кнопкой.

7. **Экономия на AI — маленькие задачи, а не «миллионы ассистентов».**
   - Каждая задача — `AiTask` с эталонами и самой дешёвой моделью, которая их проходит.
   - Простые задачи — на бесплатную квоту Gemini (D-025).
   - Где можно — код, а не модель.

## Не делаем

Ни в одном из проектов:

- скрейпинг архивов TikTok, Reels и Shorts (Apify, Playwright) — нарушает правила площадок (§2.21);
- перезалив чужих роликов с «уникализацией» (скорость, шрифт, хеш) — нарушение авторских прав;
- перенос лица на чужое видео (Animate X / ComfyUI из Guide.pdf) и дипфейк-верификация;
- фермы аккаунтов, антидетект, мобильные прокси, «биржи просмотров» — накрутка и мультиаккаунтинг.

## Alternatives

| Вариант                                           | Плюсы                           | Минусы                                                                             | Почему не выбран                                |
| ------------------------------------------------- | ------------------------------- | ---------------------------------------------------------------------------------- | ----------------------------------------------- |
| Перерисовать оба проекта в одну систему с нуля    | Одна база, один пульт           | Месяцы работы; теряются проверенные фазы и тесты; смешиваются риски завода и денег | Связь двух работающих систем дешевле и надёжнее |
| Скопировать монтаж Gen_Content в ROI Dealer (19b) | Нет зависимости между проектами | Два завода с одной логикой: двойная поддержка                                      | Один завод на оба проекта                       |
| Иерархия с «миллионами» ассистентов и ботов       | Гибкость                        | Расход и ошибки растут с числом вызовов; качество не растёт без эталонов           | Задач столько, сколько окупается                |
| Сбор чужих хитов скрейпингом                      | Много данных                    | Запрещено правилами площадок; иски (Google против SerpAPI)                         | §2.21                                           |

## Consequences

- **Плюсы.**
  - Деньги видны по каждому ролику и процессу, поэтому лишние процессы убираются кодом, а не догадкой.
  - Завод работает по болям и сезонам с доказательствами.
- **Минусы.**
  - Два проекта связаны API: нужны подпись, повторы и тесты обмена.
  - Сбой одного не должен останавливать другой.
- **Фазы, если владелец одобрит:**
  1. «Пульс» (ROI Dealer, после решения о хранении рядов чисел, 05b часть 3).
  2. «ROI процесса» (ROI Dealer, Economics).
  3. Обмен «заказ / итог» (оба проекта, ADR о протоколе).
  4. «Паттерны хитов» (Gen_Content, вместе с его Trend Radar и аналитикой).

## Rollback

До начала фаз — отклонить предложение. После — отключить обмен. Каждый проект продолжает работать сам, данные остаются в своих базах.
