# database/migrations

Версионированные SQL-миграции PostgreSQL. Применяются командой `pnpm db:migrate` (раннер из `@roi-dealer/database`, [ADR-0005](../../docs/ADR/0005-postgresql-driver-and-migrations.md)).

| Миграция                                       | Phase | Содержание                                                                             |
| ---------------------------------------------- | ----- | -------------------------------------------------------------------------------------- |
| [`0001_core_domain.sql`](0001_core_domain.sql) | 02    | 13 сущностей PHASE 01, связи, ограничения, защита истории — [схема](../docs/schema.md) |

## Правила

- **Имя файла:** `NNNN_lowercase_name.sql`, номер на 1 больше последнего. Раннер отклоняет другие имена и повторяющиеся номера.
- **Только вперёд.** Применённый файл не редактируется: раннер хранит SHA-256 каждого файла и останавливается, если содержимое изменилось. Исправление — новая миграция.
- **Одна транзакция на файл.** Раннер сам открывает транзакцию и берёт блокировку; `BEGIN` / `COMMIT` в файле не пишутся. Команды, которые не работают в транзакции (`CREATE INDEX CONCURRENTLY`), требуют отдельного решения.
- **Воспроизводимость:** миграции применяются к пустой БД в каждом integration-тесте и в CI.
- **Деструктивные изменения** (удаление таблиц и колонок, необратимые преобразования данных, снятие защиты истории) — только с approval владельца (§2.7).
- **Без секретов и реальных данных** в файлах миграций.

## Порядок в облаке

Миграции применяются до запуска новой версии сервисов. Раннер безопасен при одновременном запуске: вторая копия ждёт блокировку и пропускает уже применённые файлы.
